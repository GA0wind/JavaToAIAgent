## 1. 执行摘要

### 核心建议

**先不脱产读研，优先用 16 周完成面向 AI 应用开发岗位的能力升级，再根据真实招聘反馈决定是否需要读研。**

你不是从零开始的开发者。6 年 Java 和 Spring Boot 经验，可以迁移到 AI 应用的服务端架构、接口治理、数据库、权限、缓存、异步任务、稳定性和可观测性等环节。转型重点不是重学一遍编程，而是在原有工程能力上补充模型应用能力。

### 目标优先级

1. **主攻：大模型应用开发工程师 / AI 后端工程师**
2. **重点争取：AI 平台工程师 / 企业智能体工程师**
3. **差异化投递：金融科技 AI 工程师**
4. 暂不主攻：大模型预训练、强化学习、纯算法研究等高数学和训练经验要求的岗位

### 16 周预期产出

- 一个基于 Spring Boot + Spring AI 的可运行 AI 应用。
- 一个带来源引用、权限过滤和评估集的 RAG 知识库。
- 一组经过后端权限校验的业务工具调用能力。
- 一个包含测试、部署、日志、成本和延迟指标的项目。
- 一份架构图、README、演示材料和实测报告。
- 两个简历版本：AI 应用开发版、AI 后端 / 平台版。
- 一份目标岗位清单和一轮真实面试反馈。

> 16 周的目标是形成可验证的求职能力，不保证在固定时间内拿到 offer。结果会受到学历、城市、当前薪资、面试表现和岗位供需影响。

## 2. 读研还是直接转型

### 当前建议：先直接转型

如果主要目标是提高薪资、扩大职业机会，并希望继续利用已有后端经验，优先尝试 AI 应用开发通常比立刻脱产读研更直接。

| 情况 | 建议 |
|---|---|
| 本科及以上，计算机或相关专业，目标为 AI 应用开发 | 先做项目、投递验证，读研优先级较低 |
| 非计算机专业，但已有多年后端经验 | 用项目和面试反馈判断学历是否构成主要障碍 |
| 学历低于本科，目标岗位存在明确学历筛选 | 需要更认真地评估学历提升的收益与成本 |
| 目标是模型训练、算法研究、科研型岗位 | 考虑系统补数学、机器学习、深度学习，必要时规划硕士 |
| 希望进入特定大厂，但多轮反馈都卡在学历 | 先确认目标岗位真实要求，再决定是否读研 |

### 什么时候重新评估读研？

16 周后，用以下证据判断，而不是凭感觉：

- 投递的岗位中，多少岗位明确要求硕士？
- 面试未通过的主要原因是学历、AI 项目经验、算法基础，还是系统设计？
- 你更喜欢构建 AI 应用，还是研究模型本身？
- 读研所需时间和费用，是否能被目标岗位的长期收益覆盖？

**不要因为 AI 热度而默认读研，也不要认为不读研就能胜任所有 AI 岗位。** 应以目标岗位的真实要求决定投入。

## 3. 目标岗位与求职定位

### A 类：大模型应用开发工程师（主攻）

常见关键词：

- Java、Spring Boot、Spring AI
- 大模型 API、Prompt、结构化输出
- Embedding、RAG、向量数据库、Reranker
- Tool Calling、Agent、工作流
- 模型评估、日志、权限、安全、成本优化

这类岗位与你已有的后端开发经验衔接较自然。

### B 类：AI 后端 / AI 平台工程师（重点争取）

常见关键词：

- 模型网关、统一模型接入、限流和配额
- 异步任务、缓存、并发控制、熔断和降级
- 多租户、权限治理、审计和可观测性
- 模型耗时、Token 成本、错误率、服务稳定性

这一方向可以突出你的资深后端经验，不必将自己定位为初级 AI 开发。

### C 类：金融科技 AI 工程师（差异化方向）

可关注的场景：

- 金融产品规则和机构政策知识库
- 业务运营助手、客服辅助和内部流程自动化
- 材料字段抽取、缺失项识别、信息矛盾提示
- 审计、权限隔离、数据脱敏和人工复核

助贷行业经验是业务优势，但不应把 AI 输出直接用于自动授信或拒贷。应将项目定位为**辅助核查和流程提效工具**，并保留人工决策。

### 个人定位建议

简历和面试中不要把过去 6 年经验压缩成一句话。重点展示：

- 负责过哪些业务系统和核心链路；
- 解决过什么复杂问题；
- 如何设计服务边界、权限、事务、缓存和异常治理；
- 如何把这些工程能力迁移到 AI 应用的可靠性、安全和成本控制。

## 4. 技术栈与学习边界

### 推荐主栈

| 层次 | 技术建议 | 本阶段学习目标 |
|---|---|---|
| 业务后端 | Java、Spring Boot | 继续复用已有能力 |
| AI 接入 | Spring AI | 模型调用、Prompt、结构化输出、流式输出 |
| 检索增强 | Embedding、RAG、向量检索 | 文档处理、检索、引用和评估 |
| 向量存储 | PostgreSQL + pgvector，或熟悉的向量数据库 | 先选一种，不同时铺开多种 |
| 工具调用 | Tool Calling / Function Calling | 让模型请求工具，由后端执行并校验 |
| Agent 工作流 | Spring AI 相关能力；必要时研究 LangGraph | 状态、步骤、失败恢复和人工审批 |
| 辅助语言 | Python | 数据处理、离线评估、AI 生态工具 |
| 工程化 | Docker、自动化测试、日志、指标 | 可部署、可诊断、可复现 |
| 可选基础设施 | Redis、消息队列 | 仅在项目确实需要时加入 |

### Java 与 Python 的分工

**Java 主导应用，Python 补充 AI 生态。**

- Java：业务服务、权限、数据访问、工具接口、工作流、审计和部署。
- Python：离线评估、数据清洗、Notebook 实验，以及必须依赖 Python 库的任务。
- 模型服务：先调用可用的托管 API 或合规的内部模型服务，不要一开始就购买 GPU 或自行训练大模型。

### P0：16 周内必须掌握

- 模型 API、流式响应、结构化输出和错误处理。
- Prompt 的版本管理和测试。
- RAG 基础与检索质量评估。
- Tool Calling 与服务端权限校验。
- AI 安全、数据保护、成本和延迟监控。

### P1：有余力再学

- 混合检索、Reranker、查询改写。
- MCP、复杂工作流、长任务状态管理。
- 模型网关、语义缓存、异步队列。
- Python 数据处理和基础模型调用。

### P2：暂缓

- 从零预训练大模型、CUDA 深入优化。
- 强化学习和复杂微调。
- 同时学习多个 Agent 框架。
- 在没有评估依据时堆叠多 Agent 架构。

### 版本管理原则

Spring AI、模型 API 和相关框架更新较快。开工时先选择兼容的稳定版本，固定依赖版本，并以该版本官方文档为准。不要把不同版本教程里的代码直接拼在一起。

## 5. 每周时间分配

每周总投入 8–10 小时，建议按以下比例安排：

| 活动 | 每周投入 | 原则 |
|---|---:|---|
| 官方文档和课程 | 约 2 小时 | 只学当前项目马上用得到的内容 |
| 编码、调试和测试 | 5–6 小时 | 主动写代码，不只观看课程 |
| 复盘和求职准备 | 1–2 小时 | 记录问题、写文档、观察 JD |

建议采用 3 次学习安排，例如：

- 工作日两次，每次 1.5–2 小时；
- 周末一次，4–5 小时；
- 每次学习都留下可检查的产出：代码提交、测试、设计记录或复盘。

如果某周工作繁忙，优先完成项目主链路，不要因为课程没看完就暂停编码。

## 6. 16 周逐周学习计划

### 第 1 周：环境和模型 API

**学习内容**
- 了解 Token、上下文窗口、模型输出的非确定性、幻觉和基本参数。
- 创建 Spring Boot 项目，接入一个可用且符合个人或公司数据政策的模型服务。
- 设计统一的模型调用封装和配置管理。

**动手任务**
- 实现一个普通问答接口。
- 将 API Key 放在环境变量或安全配置中，不写进代码仓库。
- 加入超时、错误处理和基本日志。

**验收产出**
- 可以本地运行的模型调用 Demo。
- README 记录环境、配置和启动步骤。

### 第 2 周：结构化输出与流式响应

**学习内容**
- Prompt 结构、角色指令、结构化输出和流式输出。
- 模型输出不符合预期时的校验、重试和失败返回。

**动手任务**
- 实现一个返回固定 JSON Schema 的接口。
- 实现流式回答。
- 为异常和格式错误编写测试。

**验收产出**
- 一个可运行的 AI 接口服务，支持结构化结果和流式响应。

### 第 3 周：Prompt 和会话上下文

**学习内容**
- System Prompt、示例引导、输入约束和输出约束。
- 会话历史、上下文截断和多轮对话的成本。

**动手任务**
- 为业务问答设计版本化 Prompt。
- 准备 15–20 个代表性输入，比较不同 Prompt 的结果。
- 记录失败案例，而不是只保留成功截图。

**验收产出**
- 一套 Prompt 模板和第一份测试记录。

### 第 4 周：项目骨架和业务边界

**学习内容**
- 定义 Copilot 的使用场景、输入输出和不可执行的动作。
- 设计 API、数据表、日志字段和模块边界。

**动手任务**
- 建立项目目录、配置、异常模型、日志和基础测试。
- 设计文档元数据字段：来源、版本、更新时间、适用范围和权限标签。
- 使用合成数据创建最小业务资料集。

**验收产出**
- 项目骨架、架构草图、数据字典和开发计划。

### 第 5 周：RAG 基础

**学习内容**
- 文档加载、清洗、分块、Embedding、向量检索和 Top-K。
- RAG 的基本流程：检索相关片段，再将片段和问题交给模型。

**动手任务**
- 导入 Markdown 或 PDF 业务资料。
- 将文档切块、向量化并写入向量存储。
- 实现最简单的检索与回答链路。

**验收产出**
- 可以针对业务资料提问的第一版知识库。

### 第 6 周：答案引用与检索权限

**学习内容**
- 引用来源、元数据过滤、无答案处理。
- 检索阶段的权限过滤和数据隔离。

**动手任务**
- 回答展示文件名、文档版本和相关片段。
- 无足够依据时返回“资料中未找到可靠依据”。
- 设计用户、租户或角色的服务端过滤规则。

**验收产出**
- 带引用的 RAG MVP；不能只靠 Prompt 让模型自行遵守权限。

### 第 7 周：建立 RAG 测试集

**学习内容**
- 检索命中、上下文相关性、答案正确性和引用准确性。
- 错误分类：没检索到、检索错、上下文不足、模型误解、资料过期。

**动手任务**
- 建立至少 50 道人工核验的问题。
- 每道问题记录期望答案要点和应引用的来源。
- 统计初始表现，保留失败案例。

**验收产出**
- 第一份 RAG 评估集和基线报告。

### 第 8 周：检索优化

**学习内容**
- 分块策略、Top-K、相似度阈值、关键词检索和混合检索。
- 了解 Reranker 的用途和成本。

**动手任务**
- 每次只改一个关键参数，进行对照实验。
- 比较优化前后的检索命中、引用准确性和响应延迟。
- 不以单次主观体验判断优化是否成功。

**验收产出**
- 一份带实验条件和实际数据的优化报告。

### 第 9 周：Tool Calling

**学习内容**
- 工具名称、描述、参数 Schema、工具返回结果。
- 模型“请求调用工具”和应用“实际执行工具”的区别。

**动手任务**
- 暴露两个只读工具，例如查询模拟产品配置、查询模拟订单状态。
- 对参数进行服务端校验。
- 对越权、缺参数和不存在的订单进行测试。

**验收产出**
- 模型能选择工具，服务端执行后返回真实模拟数据。

### 第 10 周：业务工具安全与异常治理

**学习内容**
- 权限检查、幂等、超时、重试、重复调用和审计。
- 模型不可信输入与工具执行边界。

**动手任务**
- 用户身份由服务端认证，不接受模型自行指定身份或租户。
- 设置工具白名单、调用次数限制和超时。
- 对写操作默认不开放；若需要演示写操作，必须加入人工确认和模拟环境。

**验收产出**
- 可安全演示的工具调用流程和异常测试。

### 第 11 周：Agent 工作流

**学习内容**
- 多步骤任务、状态管理、分支、重试、终止条件和人工审批。
- 区分固定工作流和真正需要模型动态决策的任务。

**动手任务**
- 实现一个流程：理解问题 → 检索资料 → 必要时查询工具 → 生成带引用的总结。
- 限制最大步骤数和执行预算。
- 设计失败后返回明确状态的逻辑。

**验收产出**
- 一个可解释、可限制、可恢复的多步骤流程。

### 第 12 周：材料预审辅助

**学习内容**
- 结构化字段抽取、规则校验和人工复核。
- 模型输出与确定性业务规则的职责划分。

**动手任务**
- 使用合成的申请材料或虚构样例。
- 抽取字段、检查缺失项和矛盾，输出核查清单。
- 对抽取结果做格式校验和人工确认。

**验收产出**
- 一个辅助材料检查的 Demo；不做自动授信或自动拒贷。

### 第 13 周：部署、日志和指标

**学习内容**
- Docker、配置管理、日志脱敏和健康检查。
- 监控模型耗时、Token、错误率、调用成本和工具成功率。

**动手任务**
- 完成容器化部署。
- 给每次请求生成追踪标识。
- 记录必要的运行指标，但避免把敏感原文写入普通日志。

**验收产出**
- 可复现部署的项目和基本运行指标。

### 第 14 周：安全、测试和降级

**学习内容**
- Prompt Injection、越权访问、敏感数据泄漏和模型不可用。
- 失败降级、拒答策略和人工接管。

**动手任务**
- 测试恶意文档指令、越权查询、超长输入和错误工具参数。
- 对模型服务失败设置明确的降级行为。
- 检查日志、文档和演示数据是否包含敏感信息。

**验收产出**
- 安全测试清单、故障演练记录和待改进问题列表。

### 第 15 周：项目包装与简历

**学习内容**
- 项目架构讲解、技术取舍、实验结果表达。
- 面向 AI 应用和 AI 后端岗位分别提炼项目亮点。

**动手任务**
- 完成 README、架构图、演示流程和测试报告。
- 准备 3–5 分钟的项目演示。
- 建立 30–50 个目标岗位的 JD 表格。

**验收产出**
- 两个简历版本、一个项目演示和一份岗位清单。

### 第 16 周：面试与市场反馈

**学习内容**
- RAG、Agent、安全、评估、后端系统设计和项目复盘。
- 如何解释失败案例、权衡和设计选择。

**动手任务**
- 进行至少两轮模拟面试。
- 针对匹配岗位开始投递，记录简历通过率和面试反馈。
- 根据反馈确定下一阶段学习方向。

**验收产出**
- 面试复盘表、技能差距清单和下一阶段计划。

## 7. 主项目：助贷业务智能运营 Copilot

### 7.1 项目目标

开发一个模拟金融科技企业内部使用的 AI 助手，展示从模型接入到 RAG、工具调用、评估、安全和部署的完整工程能力。

所有演示资料使用**合成数据或有权使用的公开资料**。不要将真实客户资料、生产订单、身份证件、内部敏感规则上传到未经批准的外部模型服务。

### 7.2 功能模块

#### 模块 A：业务知识库 RAG

- 导入模拟产品规则、业务 FAQ、合作机构政策。
- 文档清洗、切分、向量化和检索。
- 回答展示引用来源和文档版本。
- 没有可靠依据时明确说明未找到答案。
- 通过元数据和服务端逻辑隔离不同租户或角色可访问的内容。

#### 模块 B：只读业务工具

示例工具：

- `queryProductConfig`：查询模拟产品配置。
- `queryOrderStatus`：查询模拟订单状态。
- `queryProcessNode`：查询流程节点。

要求：

- 模型只能请求调用工具，实际执行由后端完成。
- 服务端必须校验用户身份、权限、参数和数据范围。
- 工具返回最少必要数据。
- 对超时、异常和重复调用有明确处理。

#### 模块 C：材料预审辅助

- 从虚构材料中抽取约定字段。
- 识别缺失字段、格式问题和信息矛盾。
- 输出人工核查清单。
- 将模型抽取结果和确定性规则分开。
- 不将模型输出直接用于自动授信、拒贷或其他高影响决策。

#### 模块 D：评估与可观测性

- 记录检索结果、引用、工具选择和执行结果。
- 记录响应延迟、Token 使用量、错误率和估算成本。
- 评估集用于回归测试。
- 展示优化前后真实测量结果。

### 7.5 项目迭代顺序

1. 先完成单次模型调用和结构化输出。
2. 加入 RAG 和来源引用。
3. 加入测试集并记录基线。
4. 优化检索并保留实验结果。
5. 加入只读业务工具。
6. 加入多步骤工作流和人工审批。

## 8. 项目验收标准

用可验证的成果判断是否达到求职准备水平。

### 必须完成

- [ ] 模型调用、结构化输出、流式响应和异常处理可运行。
- [ ] RAG 能展示来源引用，缺少依据时不会强行编答案。
- [ ] 有至少 50 道人工核验的评估问题。
- [ ] 有检索或 Prompt 优化前后的对照结果。
- [ ] 模型可请求工具调用，但后端掌握实际执行和权限检查。
- [ ] 有超时、异常、越权、重复调用等测试。
- [ ] 有日志、响应延迟、错误率和成本统计。
- [ ] 能使用 README 中的步骤复现部署。
- [ ] 有架构图、演示和项目复盘文档。
- [ ] 所有演示数据均为合成或明确获授权的数据。

### 建议跟踪的指标

| 指标 | 说明 |
|---|---|
| 检索命中率 / Recall@K | 相关资料是否进入前 K 个检索结果 |
| 引用准确性 | 答案引用是否确实支持对应结论 |
| 回答正确性 | 与人工核验的期望答案是否一致 |
| 无依据回答率 | 缺少资料时仍给出确定性结论的比例 |
| 工具调用成功率 | 工具是否选对、参数是否有效、执行是否成功 |
| P50 / P95 延迟 | 常见和较慢请求的响应耗时 |
| 单次调用成本 | 按所用模型的实际计费方式估算 |
| 安全测试通过率 | 越权、注入、异常参数等用例的通过情况 |

不必一开始追求某个漂亮的固定百分比。先建立基线，再用测试结果说明优化效果和剩余问题。不同数据集和模型之间的数字不可直接比较。

## 12. 风险、常见误区与复盘机制

### 避免以下误区

- **只看课程不写代码：** 每周必须产生代码、测试或文档。
- **追逐框架：** 先精通 Spring AI，再按岗位要求研究其他框架。
- **把 Demo 当产品：** 没有评估、安全、权限和故障处理的聊天 Demo 不足以证明生产能力。
- **过早研究训练：** 目标是应用开发时，不必先投入大量时间学习 GPU 和预训练。
- **编造项目数据：** 所有性能、准确率和成本数字都应可复现。
- **直接使用公司数据：** 使用合成或获授权的数据，遵守公司政策和适用的数据保护要求。
- **让模型直接做高影响决定：** 信贷、授信等场景保留明确规则、人工复核和审计。

### 每周复盘模板
