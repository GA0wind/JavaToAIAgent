## JAVA-01｜Spring AI 在业务系统里负责哪一层？

- 优先级：P0；依据：[F04](../../02-resources/official-docs/foundation-sources.md#f04)、[F06](../../02-resources/official-docs/foundation-sources.md#f06)、[F07](../../02-resources/official-docs/foundation-sources.md#f07)。
- 考察点：框架与业务职责。
- 回答要点：用模型、向量与工具抽象组织 AI 调用；`ChatClient` 负责调用流程，`ChatModel` 连接模型抽象，Advisor 组合上下文和检索等行为。身份认证、领域规则、事务及资源授权仍归业务后端，不能靠 Prompt 替代。
- 追问：更换提供商是不是零成本？模型能力、参数、错误、流式事件及工具语义仍需兼容性验证。
- 验证要求：画出 Controller 到模型、向量库和业务工具的调用关系，标明鉴权位置。

## JAVA-02｜模型返回 JSON 并转成 DTO，是否就可靠了？

- 优先级：P0；依据：[F05](../../02-resources/official-docs/foundation-sources.md#f05)。
- 考察点：格式与业务语义分层。
- 回答要点：Prompt 请求 JSON、文本转换和提供商原生 Schema 约束是不同机制；成功映射 DTO 仍可能缺字段、数值越界、事实错误或越权。继续做 Schema / Bean Validation、领域校验与来源核对；错误需有明确失败返回和有限重试。
- 追问：枚举合法，但结论没有依据怎么办？保留缺失状态或拒绝输出确定结论，不能用合法枚举掩盖未知。
- 验证要求：设计合法 JSON 但业务非法的例子，说明在哪一层拒绝。

## JAVA-03｜流式输出为什么不能收到一段就解析成最终 JSON？

- 优先级：P0；依据：F04；SSE 事件方案为工程设计。
- 考察点：增量响应、取消和中途失败。
- 回答要点：流片段可能截断字段或语法结构，应聚合后解析，或采用明确支持增量的解析与校验方案。区分文本、工具状态、错误和结束事件；处理浏览器断开与上游取消。首 Token 更快不代表整个请求更快。
- 追问：已经发出 HTTP 200，后续模型失败怎么办？使用约定的流内错误事件并正确结束，客户端不能把部分结果标为完整成功。
- 验证要求：写出“内容片段 → 错误 → 结束”的事件序列及前端状态变化。

## JAVA-04｜模型调用很慢，如何避免耗尽线程和连接？

- 优先级：P0；依据：[F10](../../02-resources/official-docs/foundation-sources.md#f10) 支持观测部分；并发策略为后端设计。
- 考察点：资源预算与故障放大。
- 回答要点：限制在途请求和排队，设置连接及响应超时、端到端预算；选择匹配负载的执行方式，避免事件循环执行阻塞调用。只对适当临时故障做有限退避重试，配合限流、熔断、取消和明确降级；虚拟线程也不能消除下游配额限制。
- 追问：一次用户请求触发多轮工具调用，预算怎么计算？所有模型、工具、排队和重试都要计入同一任务预算。
- 验证要求：设计下游持续超时的实验，列出队列长度、在途数、错误率和延迟观测点。

## JAVA-05｜如何设计日志、指标和业务链路追踪？

- 优先级：P0；依据：F10。
- 考察点：可诊断性与数据边界。
- 回答要点：串联请求、模型、检索、工具的 trace，记录模型标识、Prompt 版本、Token、耗时和错误分类。指标标签保持低基数，用户 ID 等不直接作为指标标签；原文与敏感参数不默认导出，trace 也需控制权限。
- 追问：只看模型耗时能解释整个接口慢吗？不能，需区分排队、召回、重排、工具和多轮调用。
- 验证要求：列出一条虚构慢请求所需字段，说明哪些脱敏、哪些进入指标或 trace。
