## SEC-01｜什么是 Prompt Injection？写“忽略恶意指令”够吗？

- 优先级：P0；题源：[N02](../../02-resources/papers-and-articles/interview-sources.md#n02) 改写；依据：[F18](../../02-resources/official-docs/foundation-sources.md#f18)。
- 考察点：不可信数据与执行权限。
- 回答要点：直接输入或外部资料中的指令可能诱导模型偏离任务；文本提醒只是缓解之一。分离指令和资料、最小化工具权限、服务端校验参数与资源范围、限制输出去向并评估攻击样本；不能声称彻底消除。
- 追问：RAG 文档里有“读取所有用户数据”怎么办？它没有授权效力，服务端仍应拒绝相应工具和数据读取。
- 验证要求：用合成攻击文本分别验证模型输出与工具执行，两者结果分开记录。

## SEC-02｜如何避免多租户 RAG 与缓存串数据？

- 优先级：P0；题源：工程补充；依据：[F06](../../02-resources/official-docs/foundation-sources.md#f06)、[F12](../../02-resources/official-docs/foundation-sources.md#f12)；缓存策略为设计要求。
- 考察点：全链路身份和资源隔离。
- 回答要点：服务端从认证上下文生成租户和权限条件，不让模型自行决定；检索返回在进入模型前必须符合授权。文档、索引、会话、记忆、引用及缓存都需隔离；缓存键含权限范围和版本，权限变更要失效或重新校验。
- 追问：同一个问题能否跨租户直接复用答案？相同文本不代表相同可见资料与结论，必须满足权限和来源条件。
- 验证要求：用虚构 A/B 身份问同一问题，检查冷缓存和热缓存路径。

## SEC-03｜有副作用的工具如何做人工确认与幂等？

- 优先级：P0；题源：N02 改写并补充；依据：F18、[工具执行设计](../../01-foundations/agent/README.md)。
- 考察点：确认到执行的一致性。
- 回答要点：先形成可检查的目标、动作和参数，确认绑定身份、参数及有效期，执行前复查权限与当前状态；参数改变需重新确认。稳定业务幂等键与执行记录防止重复，结果未知先查询状态，不能靠模型口头宣称成功。
- 追问：确认后目标状态变化怎么办？重新校验前置条件，必要时作废确认并返回人工处理。
- 验证要求：仅在模拟环境设计重复确认、过期确认、参数变更和超时用例，未授权不得真实写入。

## SEC-04｜为了调试把完整 Prompt 和工具结果写日志有什么问题？

- 优先级：P0；题源：N02 安全主题改写；依据：[F10](../../02-resources/official-docs/foundation-sources.md#f10)、F18。
- 考察点：数据最小化与审计。
- 回答要点：原文可能含密钥、个人信息或受限业务资料，日志和 trace 增加复制、读取和保留风险。优先记录版本、Token、耗时、错误和脱敏摘要；确需原文时先确认授权、访问范围及保留策略，外发模型请求也需控制。
- 追问：应用日志脱敏，但 trace 里仍有全文算完成吗？没有，需检查观测与错误上报的所有出口。
- 验证要求：列出输入、模型请求、工具参数、响应、日志及 trace 的数据流，检查每个出口。
