# 评估

目标：把“感觉回答更好”变成条件明确、可复查的比较。关联第 3、7～8、13～14 周；[面试题 EVAL-01～05](../../04-interview/question-bank/evaluation.md)。整理日期：2026-11-05；个人掌握与实践状态：未开始。

## 分层评估

| 层次 | 检查什么 | 如何避免误读 |
|---|---|---|
| 数据与解析 | 资料是否完整，版本、条件是否保留 | 原资料无答案时不能把失败全归咎于模型 |
| 检索 | 相关证据是否进入候选，排名是否靠前 | 检索好不代表最终答案好 |
| 回答 | 正确性、证据支持、引用和无答案处理 | 通顺或有链接不能代替事实核验 |
| 工具与任务 | 工具选择、参数、执行、最终任务是否正确 | HTTP 200、工具成功、任务成功是不同事件 |
| 运行质量 | 延迟、错误、Token、费用与权限拒绝 | 只报平均值会掩盖慢请求与失败 |

评估器与模型评审方法见 [F11](../../02-resources/official-docs/foundation-sources.md#f11)；观测能力见 [F10](../../02-resources/official-docs/foundation-sources.md#f10)。以下指标口径为本仓库练习约定，应和具体数据集一起保存。

## 检索指标

设 `R_q` 为问题 q 的人工标注相关证据集合，`T_q(K)` 为前 K 个检索结果；必须统一用文档 ID 或片段 ID，不能混用粒度。

- `Recall@K(q) = |R_q ∩ T_q(K)| / |R_q|`：相关证据找回多少。
- `Hit@K(q) = 1`（至少命中一条相关证据），否则为 0；数据集上取平均。
- `MRR@K`：每问第一个相关结果排名的倒数；前 K 内未命中记 0，再求平均。

**虚构算例**：相关片段为 `{A, B}`，前 3 条为 `{A, X, Y}`，Recall@3 是 `1/2`，Hit@3 是 `1`。不能因为命中一条就宣称召回率 100%。无答案问题的 `R_q` 为空，不直接参与上述 Recall 计算，单独统计拒答行为。

## 回答指标与数据集

人工正确性按预先写好的答案要点评分；忠实度检查回答是否由给定证据支持，证据本身过期时仍可能“忠实但错误”。引用支持率可定义为“被引用片段支持的声明数 / 带引用的声明数”，还应单独看需要依据的声明是否都有引用。无依据回答率须说明分母是无答案问题数还是全部问题数。

数据集记录问题、答案要点、来源与版本、权限身份和场景标签。覆盖可回答、不可回答、矛盾、过期、跨租户和工具故障。调参集与保留测试集分开，避免在同一批题上反复优化后声称泛化提升。

LLM-as-judge 可辅助扩展评审，但有偏差和不稳定性；固定评分规则及评审模型标识，抽样人工复核，并将格式校验、权限断言交给确定性代码。

## 对照实验与观测

固定问题集、文档版本、模型及 Prompt；一次改变一个主要因素，记录样本量、失败项与重复测量差异。性能区分首 Token 时间和完整响应时间，报告 P50 / P95 及失败率，明确并发、超时和取消样本处理方式。

若按 Token 计费，可先估算 `输入Token×输入单价 + 输出Token×输出单价`（单位一致），再纳入缓存、额外推理计费、Embedding、重排和多轮工具调用等实际项。本文不填写价格；实际实验当天查提供商计费规则。
