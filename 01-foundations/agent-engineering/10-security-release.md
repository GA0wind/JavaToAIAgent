# 第 10 章：安全与上线

## 学习目标

能把模型功能放进明确的身份、权限、数据和运行边界中；上线前检查提示注入、工具滥用、资源消耗和故障行为。

## 定义、原理与设计原因

- **Prompt Injection**：不可信输入（用户内容、检索文档、工具输出等）试图改变模型行为、泄漏信息或诱导工具动作。模型提示可以帮助识别，但不能作为唯一安全边界。
- **最小权限**：每个工具只持有完成单项任务所需的最小数据和动作范围，并按当前认证用户/租户做服务端授权。
- **资源预算**：对请求时长、Agent 步数、并发、重试、输入/输出 Token 和费用设上限，避免无限调用或成本失控。
- **降级与人工接管**：模型或工具失败时回退到安全且明确的状态；高风险或不确定动作由人审核。

采用纵深防御的原因是提示、模型输出和检索内容都可能不可信；真正的权限必须由服务端执行。输入校验、工具白名单、数据过滤、输出验证、审计和人工确认分别控制不同失效点。超时限制挂起，退避重试缓解瞬时故障，熔断保护下游；但重试有副作用的工具必须先保证幂等。上线时还要管理密钥、脱敏日志、健康检查、配置、并发、可观测和回滚。

## 常见面试考察方向（非频率统计）

1. **Prompt Injection 如何防御？**答题线索：不依赖单条系统 Prompt；分离可信指令与不可信数据、最小权限、工具白名单/校验、数据过滤、输出检查、高风险人工审批和攻击测试组合使用。
2. **如何避免 Agent 越权？**答题线索：身份由认证中间件提供；每次工具调用按用户/租户重新授权，不能采信模型自报身份或文档中的指令。
3. **模型调用失败怎样重试/降级？**答题线索：区分限流、超时、格式错误与业务错误；设置总预算、指数退避/抖动、熔断；写操作通过幂等键或先查状态，失败时返回明确状态。
4. **上线前最低限度需要哪些保障？**答题线索：配置/密钥安全、超时预算、授权隔离、健康检查、审计与脱敏 Trace、评估/安全用例、发布回滚和人工接管路径。

## 安全边界

- 提示注入可能来自用户、检索文档或工具返回。提示词可以提醒模型，但不是安全控制；用服务端权限、白名单、输出校验、数据过滤和人工确认建立真正边界。
- 身份来自认证上下文，不来自模型生成内容。每个工具按当前用户和租户授权，默认最小权限；高影响写操作需明确授权与审计。
- 对输入、输出和外部工具结果做适当校验；限制文件、网络、数据库和 shell 能力。把知识检索权限过滤前置到查询阶段。
- 设置请求/总任务超时、步数上限、并发与速率限制、单任务 Token/费用预算。重试需考虑幂等、退避和供应商限流。
- 密钥使用安全配置注入；日志脱敏，定义数据保留周期。模型输出经业务校验后才能影响应用状态。

## 上线与部署

以 FastAPI 为例，课程图指向服务化部署练习；本项目 Java 主线仍按 Spring Boot。无论语言，都需要健康检查、配置区分、依赖超时、并发限制、指标与追踪、容器/部署说明和回滚路径。框架或服务器本身不等于生产就绪。

## 实践与验收

制作一组攻击与故障用例：检索内容指令劫持、跨租户查询、超大输入、工具连续失败、超时、模型限流、成本预算耗尽。证明系统拒绝或受控终止，且不会泄漏其他用户数据。保存脱敏测试结果与已知限制；未实际部署前不宣称已安全上线。
