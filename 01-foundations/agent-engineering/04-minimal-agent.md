# 第 4 章：手写最小 Agent

## 学习目标

不依赖 Agent 框架，理解模型发起工具调用后由应用接管的循环；实现明确的终止、预算、错误分类和逐步 Trace。练习是概念验证，不直接用于生产。

## 定义、原理与设计原因

最小 Agent 循环是一个应用控制的状态机：**请求模型 → 判断最终答复或工具请求 → 校验并执行工具 → 把结果放回上下文 → 再请求模型**。模型生成的是动作建议，不是已发生的业务操作。

循环让模型能依据刚取得的新观察选择后续动作，避免用户手工多轮转述。但每增加一步都会引入模型决策、工具失败、超时、费用和状态不一致的机会。因此必须设最大步数、总时间、调用/Token 预算、允许工具清单、终止状态和人工接管点。逐步 Trace 记录可审计的动作与结果，不需要记录或宣称模型的隐式思维链。

## 常见面试考察方向（非频率统计）

1. **一次 Tool Calling 到最终答复经历哪些步骤？**答题线索：传工具 Schema、解析请求、服务端白名单/参数/权限校验、真实执行、返回结果消息、模型继续或结束。
2. **如何防止 Agent 无限循环？**答题线索：步数/时间/费用预算、重复调用检测、状态机终态、错误分类、熔断与明确停止结果。
3. **若每步成功率是 95%，20 步整体成功率是多少？**答题线索：在独立同分布这一简化假设下为 `0.95^20≈35.8%`；它是说明误差累积的直觉，不是实测 Agent 成功率。
4. **模型报告工具成功但后端实际失败，信谁？**答题线索：以真实工具结果和业务状态为准，模型总结必须基于可验证结果。

## 控制循环

```text
读取用户请求与认证上下文
在最大步数、总时长和调用预算内：
  调用模型
  若模型给出最终回答：按证据和输出契约校验后结束
  若提出工具调用：检查白名单、参数 Schema、权限与审批要求
    执行工具，记录结果状态，将最少必要结果交回模型
  若响应无法识别或工具失败：分类失败，按策略结束或有限重试
预算耗尽：返回可解释的停止状态
```

模型提出调用不等于调用成功；应用根据实际工具执行结果更新状态。每一步记录 trace/span 标识、步骤序号、耗时、模型响应类别、工具名称、脱敏参数摘要、状态和错误类别，避免将敏感内容写入日志。

## 可靠性直觉

如果每一步成功概率假设为 0.95，且各步独立，连续 20 步全成功的概率为 `0.95^20 ≈ 35.8%`。这是教学用的简化假设，不是实测 Agent 指标；真实步骤并不一定独立，成功概率也可能不同。它提醒我们控制步骤数、验证中间结果并设计恢复。

## 实践与验收

先实现一个只读模拟工具，例如查询合成文档编号的状态。覆盖成功、参数缺失、越权、超时、重复工具请求、模型持续要求调用和格式错误。验收：达到预算必停、调用权限由服务端确定、失败状态可定位、工具结果不会被冒充为用户授权。
