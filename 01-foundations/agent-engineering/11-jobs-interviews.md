# 第 11 章：岗位与面试

## 学习目标

将目标岗位描述转换为能力清单与学习优先级；以真实证据回答常见 Agent 工程问题，而不是背框架名词或声称未做过的成果。

## 定义、原理与设计原因

- **JD 能力映射**：将岗位要求逐条映射到当前技能、作品集证据、差距和验证任务。它帮助决定学习优先级，不用于推断整个招聘市场。
- **高频面试题**：本资料按仓库现有题库、课程模块与公开题源整理的常见考察方向；不承诺统计某家公司或市场真实出现频率。
- **三层追问**：先确认概念边界，再问工程实现与取舍，最后追到失败案例、数据证据和局限。
- **证据化回答**：把判断锚定到亲自做过的代码、测试、Trace、评测或复盘；未验证的计划必须明说是计划。

这样准备是因为面试不仅检查名词记忆，也会沿着答案追问系统边界、错误处理和实际验证。Java 后端经验可以支撑服务治理、鉴权、并发和可观测性；AI 相关能力要以模型调用、RAG、工具和评测证据补齐。岗位市场与 JD 会变，所以只将公开 JD 用作当前目标样本，不写成普遍规律。

## 常见面试考察方向（非频率统计）

1. **如何拆解一条 JD？**答题线索：区分应用开发/平台/算法；记录语言、模型、RAG、Agent、安全和部署要求；逐条关联证据与缺口，再选优先级最高的练习。
2. **面试官问“你做过 Agent 项目吗”怎么回答？**答题线索：说明本人实际实现范围、系统边界、一次具体故障、验证方式和当前限制；不把课程示例或计划说成已完成项目。
3. **如何回答不会或未做过的问题？**答题线索：先明确已知/未知，基于原理推理，指出需要验证的假设；不编造测试结果和经验。
4. **一题如何承接三层追问？**答题线索：定义和边界 → 实现/权衡 → 失败/数据/反例/局限。用真实证据闭环。

## 拆解岗位 JD

每条要求标注为：已有 Java/Spring 工程能力、待补模型应用能力、明确要求的框架/语言、可用项目证据、缺口和验证方式。区分岗位是在做 AI 应用、平台后端、数据/模型工程还是算法研究。记录招聘来源、发布日期/抓取日期和原始链接；招聘信息会过期，不把单条 JD 当市场结论。

## 主题练习

先按模块整理高频题，再做三层追问：第一层解释概念和适用边界；第二层说明实现、取舍和故障处理；第三层给出评测证据、反例和仍有限制。练习问题包括：什么时候选 Workflow 而不是 Agent？工具调用权限如何控制？RAG 错误如何定位？如何处理上下文超限？模型超时与重复写调用怎么办？如何评估一次 Prompt 或检索改动？如何发现并处置 Prompt Injection？

回答结构建议：问题和约束 → 方案 → 关键取舍 → 失败与验证 → 当前限制。安排一轮模拟面试，逐题记录原回答要点、亮点、缺口和后续练习。题库现有答案用于自测提示，不是个人掌握证据。

## 实践与验收

选取 5 条真实公开 JD，去除个人敏感信息后形成岗位矩阵；每个高优先级缺口指定仓库中的章节和验收产物。录制或文字记录一次模拟面试，按正确性、工程深度、表达和证据可信度复盘。岗位名称、薪资、市场需求等动态信息需在使用当日核验。
