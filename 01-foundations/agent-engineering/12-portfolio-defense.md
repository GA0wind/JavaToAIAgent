# 第 12 章：作品集、简历与结课答辩

## 学习目标

把可运行的项目、评测与复盘整理成别人可以核查的作品集；用简历和答辩准确说明自己做了什么、测得什么、还有什么限制。

## 定义、原理与设计原因

- **可展示项目**：第三方能理解目标、按文档复现核心流程，并查看测试/评估证据的工程产物。只有截图或一个聊天页面不足以证明可靠性。
- **评测报告**：记录数据集、方法、指标、基线、变化、逐例失败和限制的实验说明。
- **量化简历**：将效果数字绑定到可复现的测量方法、样本和时间范围；没有实测数据就写真实功能和职责，不估造指标。
- **技术复盘**：解释为何选某方案、失败在哪里、如何定位修复、还存在哪些风险。

作品集要同时证明“能构建”和“知道边界”。因此需展示正常路径、失败路径、真实评测以及安全/部署条件；用合成或获授权数据确保演示可分享。答辩不追求隐藏限制，而要说明当前证据支持什么结论、不能支持什么结论。简历中的每条功能或数字都应能追溯到代码、测试、报告或提交。

## 常见面试考察方向（非频率统计）

1. **怎样证明项目不只是 Demo？**答题线索：可复现启动、边界清楚、异常/权限测试、固定评测集、可观测记录和部署说明。
2. **如何量化项目成果？**答题线索：给出指标定义、数据集大小/来源、基线、环境、测量方式和不确定性；没有数据时不编数字。
3. **项目答辩怎样讲一个失败案例？**答题线索：症状、定位证据、根因、改动、回归验证、仍有限制；展示过程而不只展示成功截图。
4. **课程项目与个人项目如何写进简历？**答题线索：标明个人实现范围和使用数据；分清学习练习、规划、真实工作经历，不把他人代码或课程成果冒充自己的交付。

## 作品集材料

- 可访问且有启动说明的项目版本；使用合成或获授权数据。
- 架构图、需求范围、主要数据流、权限与故障边界。
- 评测集说明、真实实验结果、失败案例和 Trace 截图；遮蔽令牌、个人信息和敏感内容。
- 一篇复盘：问题定义、关键取舍、定位过程、效果证据、局限和下一步。
- 简历条目对应到代码、测试、报告或演示证据。区分真实工作经历、个人项目实现与未来规划。
- 量化简历只写能复现的指标：说明数据集、基线、测量方法和样本范围；尚无实测结果时用功能和工程证据描述，不填推测数字。

## 结课答辩结构

按“需求 → 工具/模型 → 评测 → 上线边界 → 取舍”讲清楚：用户痛点和范围；关键链路；一个失败案例及如何定位；评测方法与实际结果；权限、安全、成本和可用性；仍未解决的问题。现场演示预备成功路径与失败路径，不只展示一段理想回答。

## 本仓库落地

作品集主线是 [Loan Platform Engineering Copilot](../../03-projects/loan-platform-engineering-copilot/README.md)。现有仓库只有项目框架，没有运行实现、评测报告或实测 Trace。不得把计划章节改写成完成经历，也不得把课程中的示例 Agent 当作自己的成果。

## 验收

他人按说明能在约定环境中复现；演示覆盖一条成功和一条失败路径；简历中的每项功能都能指向证据；答辩能解释取舍和局限。实际达成后再更新阶段进度，并保存复盘记录。
