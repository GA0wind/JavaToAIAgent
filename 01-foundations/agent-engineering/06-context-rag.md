# 第 6 章：上下文与 RAG

## 学习目标

解释一次模型调用的上下文由哪些部分组成，能搭建从资料进入到带来源回答的最小 RAG，并定位解析、分块、检索、重排或生成环节导致的错误。

## 定义、原理与设计原因

- **RAG（Retrieval-Augmented Generation）**：回答时先从外部知识源检索候选证据，再将问题和选定证据交给生成模型。它把可更新知识放在外部资料中，而不要求每次更新都训练模型。
- **索引阶段**：解析、清理、保留来源/版本/权限元数据、切块、生成 Embedding 并存储。
- **查询阶段**：身份过滤、查询变换（按需）、关键词/向量召回、候选融合与重排、上下文预算、生成答案、映射引用并检查证据。
- **Chunk**是被检索和送入上下文的文档片段；切块要在语义完整、检索精度、上下文长度和来源追踪之间权衡。
- **Hybrid Search**组合词项匹配和语义向量召回；**Reranker**对已召回候选重新排序，不会找回根本未被召回的证据。

为什么先检索再生成：参数化模型知识难以快速更新、来源不易追溯；外部检索可给出当前材料和出处。但 RAG 只改善可用证据，解析错误、切块不当、召回遗漏、权限过滤失效或模型误读仍会导致错误。引用要绑定实际检索片段，不能由模型临时编造。

## 常见面试考察方向（非频率统计）

1. **RAG 的完整链路和主要失败点是什么？**答题线索：解析、切块、索引、召回、过滤、重排、上下文组装、生成、引用核验；按阶段定位失败。
2. **Chunk 大小和 overlap 如何选？**答题线索：没有通用最优值；由文档结构、问答粒度、检索指标和上下文预算决定。Overlap 可保留跨边界信息，但过大会产生重复噪声。
3. **向量检索、BM25、混合检索、Reranker 如何分工？**答题线索：语义召回、词项精确匹配、候选合并、候选重排；需用固定评估集比较。
4. **如何实现 RAG 权限隔离和可信引用？**答题线索：在服务端基于认证身份做检索过滤；每个引用关联文档 ID/版本/片段；不足或冲突时澄清、拒答或给出限制。

## 数据流

```text
授权资料 → 解析与清理 → 保留来源/版本/权限元数据 → 切块 → Embedding/索引
问题 → 身份与权限过滤 → 关键词/向量检索 → 合并与重排 → 上下文预算
     → 模型生成 → 引用映射/证据检查 → 答复或澄清
```

切块要保留标题、页码、版本、租户和源 ID 等可追溯信息；不能把不同权限范围的片段混进同一可见结果。混合检索组合关键词与向量召回，重排调整候选顺序，但都需要通过评估数据判断是否有益。上下文压缩需保留否定、条件、时间范围和来源，不可只按长度删减。

记忆与 RAG 不同：会话状态承载当前任务；长期记忆是带来源、权限、期限和删除方式的持久化信息。聊天历史不应自动全部作为记忆。

## 实践与验收

用标记为虚构的 5–10 篇说明文档建立小型语料。先固定查询集和相关文档，再比较至少两种切块或检索设置。记录 Recall@K、正确引用与未命中问题；资料不足时检验系统是否澄清或拒答。评估必须注明样本量和局限。
