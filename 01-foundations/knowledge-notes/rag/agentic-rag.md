# Agentic RAG

## 定义
Agentic RAG 是将检索作为 Agent 可选择或迭代的能力：Agent 可以决定是否检索、如何改写查询、何时追加检索，以及是否需要另一种数据源。它不同于每次请求都固定执行同一条检索管线。

## 原理
围绕目标执行“判断信息缺口 → 调用检索工具 → 检查结果 → 改写/继续/回答或拒答”。可用验证器、轮数/成本预算和明确终止条件限制循环；检索输出始终作为证据而非指令。

## 为什么这样设计
固定 RAG 对常见单跳问题高效；需要多轮调查、跨数据源或根据证据动态选择查询时，Agentic RAG 提供弹性。代价是更多模型调用、延迟、不可预测性和工具攻击面。

## Java 工程关联
先以固定 RAG 建立基线，仅当失败样本说明需要动态检索时再升级。检索工具执行租户过滤、来源记录和调用预算；评测比较端到端质量、成本与延迟。

## 高频面试题
1. **Agentic RAG 和普通 RAG 的区别？**答题要点：普通 RAG 通常固定检索/生成流程；Agentic 允许模型按中间观察动态控制检索。
2. **何时不应使用 Agentic RAG？**答题要点：固定查询已够用、延迟/成本严格、路径可确定或风险较高时。
3. **如何避免循环检索？**答题要点：预算、重复查询检测、充分证据/无答案终止和追踪评测。

## 自测
为含多份互相矛盾政策文档的问题设计固定 RAG 与 Agentic RAG 两套流程，并用同一评测集比较。
