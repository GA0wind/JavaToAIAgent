# 元数据过滤与租户隔离检索

## 定义
元数据过滤是在语义搜索前或过程中按文档标签、时间、类型、租户或权限范围筛选候选。它决定“哪些数据可以参与检索”，与相似度排序回答“哪些候选更相关”是两类问题。

## 原理
索引记录携带可查询元数据；服务端从已认证用户的授权上下文生成过滤条件，并与检索查询绑定。不能让模型自行提供租户 ID 或最终权限表达式。

## 为什么这样设计
先做授权范围约束可避免跨租户或越权内容泄漏；过滤还能缩小搜索范围、提高业务相关性。权限变更和文档撤权需及时反映到索引。

## Java 工程关联
从认证主体/服务端租户映射构建过滤器，拒绝客户端或模型篡改；过滤后再次校验结果来源。测试不同租户、角色、过期文档和无权限但语义相近内容。

## 高频面试题
1. **为什么不让 Prompt 要求模型忽略别的租户资料？**答题要点：提示词不是访问控制，未授权内容一旦进入上下文已泄露。
2. **过滤失败如何安全处理？**答题要点：默认拒绝或不返回数据，不能退化为全库检索。
3. **向量库过滤等同业务授权吗？**答题要点：是防线之一，仍应有可信身份来源、服务端校验和审计。

## 自测
构造两个虚构租户的相似文档，验证跨租户问题不返回另一方片段。
