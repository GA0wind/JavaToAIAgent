# 对话记忆与长期记忆

## 定义
记忆是应用跨模型调用保存和检索信息的机制。短期对话记忆通常是当前会话历史/状态；长期记忆把较稳定、可能跨会话有用的信息持久化并按需召回。

## 原理
每轮请求从存储加载相关历史或事实，合并到上下文；生成后按策略更新状态。记忆可存关系型数据、事件日志或向量索引，不应把“全部历史都发给模型”当作唯一方案。

## 为什么这样设计
大多数模型 API 对单次请求无状态，应用必须自行实现跨请求连续性。分层存储可兼顾精确状态、检索灵活性、成本和隐私要求。

## Java 工程关联
用 conversation ID、用户/租户 ID 和访问控制隔离记忆；定义保留期、删除、纠错和导出机制。可变业务状态优先由数据库作为事实源，模型摘要仅作辅助。

## 高频面试题
1. **上下文窗口就是记忆吗？**答题要点：不是，窗口只限制单次输入，记忆需要应用持久化和召回。
2. **什么信息适合长期记忆？**答题要点：稳定且有明确用途的信息；遵守授权、最小化、过期和删除规则。
3. **记忆错误如何纠正？**答题要点：保留来源与时间、允许更新/撤销，权威业务数据回到事实系统查询。

## 自测
设计多轮会话表与记忆检索接口，说明租户隔离和记忆删除如何工作。
