# 上下文压缩

## 定义
上下文压缩是从历史消息或检索候选中提取完成当前任务所需信息，以减少 Token 占用的过程，可采用截断、摘要、去重、结构化状态或按相关性选择。

## 原理
应用设定预算，优先保留当前任务约束、最近相关交互、来源和未完成事项；被压缩部分可保留摘要及原始记录引用。生成式摘要本身也可能漏掉否定、数字和条件。

## 为什么这样设计
有限上下文要求控制输入长度、成本和噪声。压缩能让系统处理长对话或大批文档，但需要权衡信息损失和延迟。

## Java 工程关联
摘要要有版本与来源，必要时保留原始对话 ID；预算按 Token 估算，不能简单按字符截断。重要字段优先结构化存储，避免仅靠摘要记住业务事实。

## 高频面试题
1. **摘要记忆会丢什么？**答题要点：时间、否定、精确数字、来源和低频但关键事实，须有保留策略。
2. **如何验证压缩质量？**答题要点：对比压缩前后任务指标和事实保留率，特别测试边界案例。
3. **截断和摘要如何选？**答题要点：看时延、可追溯性和事实精度；关键业务状态用结构化记录。

## 自测
对多轮虚构对话压缩成状态对象，检查关键约束、来源和未完成操作是否保留。
