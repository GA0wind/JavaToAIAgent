# MCP 传输、会话与生命周期

## 定义
传输层负责 MCP 消息在 Client 与 Server 之间如何交换；生命周期涵盖连接初始化、版本/能力协商、请求处理、通知、取消和关闭。传输选择不改变业务授权要求。

## 原理
常见场景包括本地进程标准输入输出（stdio）和远程 HTTP 传输；连接建立后协商支持能力，客户端按能力调用方法。长任务可涉及进度、取消或会话状态。

## 为什么这样设计
同一协议可用于本地工具和远程服务，允许根据部署边界选择传输；显式生命周期使双方可处理版本兼容、资源释放和任务取消。

## Java 工程关联
选择传输需考虑网络暴露、凭证、进程管理、并发和可观测性。远程服务配置 TLS/认证/限流；本地 stdio 也需防止启动不可信程序和继承敏感环境。

## 高频面试题
1. **stdio 和 HTTP 传输如何选？**答题要点：部署位置、网络暴露、运维能力和客户端支持；没有普适单选。
2. **能力协商失败怎么办？**答题要点：拒绝不兼容连接或降级到双方明确支持的子集，不猜测调用。
3. **取消请求后要做什么？**答题要点：传播取消、停止可取消工作、释放资源并记录最终状态。
