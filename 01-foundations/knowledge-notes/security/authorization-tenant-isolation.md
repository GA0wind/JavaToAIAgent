# 身份、权限与租户隔离

## 定义
认证确认调用者身份；授权决定其可执行的动作和可读取的数据；租户隔离确保不同组织/客户的对象在查询、缓存、记忆、日志和工具执行中不互相暴露。

## 原理
从可信身份提供方取得主体与租户上下文，服务端基于策略检查每个资源和操作；模型只能看到授权后最小必要信息。用户可控字段不能直接成为授权依据。

## 为什么这样设计
LLM 应用会将用户请求转为检索和工具操作，若权限只靠前端或提示文字保护，越权输入即可绕过。服务端强制校验能将权限规则与随机生成隔离。

## Java 工程关联
在服务边界提取认证主体，方法/数据访问都按租户过滤；Cache key、向量查询、记忆、异步任务和导出链路均携带授权范围。默认拒绝，并测试 IDOR/越权路径。

## 高频面试题
1. **为什么不能让模型判断用户有没有权限？**答题要点：模型是概率组件，不是身份权威；授权应由确定性后端执行。
2. **多租户检索如何防串租？**答题要点：可信租户上下文强制过滤、结果二次校验、隔离测试和审计。
3. **缓存容易漏什么？**答题要点：缓存键漏租户/权限维度、权限撤销后旧数据仍可读。

## 自测
列出请求、RAG、工具、记忆、缓存和异步处理各处租户上下文的来源与校验点。
