# 权限沙箱与执行隔离

## 定义
沙箱是对代码、工具或 Agent 可访问的文件、网络、进程和资源施加隔离与配额的执行环境。它通过限制影响范围降低不可信输入导致的损害。

## 原理
按最小权限创建隔离身份/容器，限制可挂载路径、网络出口、CPU/内存/时间和系统调用；对允许的操作使用白名单。容器本身也须正确配置，不能等同于绝对安全边界。

## 为什么这样设计
代码执行、文件操作和网络请求可能有副作用；将其与主应用和敏感资源隔离，可限制越权读写及资源耗尽。

## Java 工程关联
不要让模型生成 Shell 后直接以应用账户执行。需要执行时用独立低权服务、只读挂载、网络白名单、临时目录、超时和审计；生产凭证不进入沙箱。

## 高频面试题
1. **Docker 容器就是安全沙箱吗？**答题要点：不自动是；需权限收缩、隔离配置、运行时防护和宿主加固。
2. **沙箱网络如何配置？**答题要点：默认关闭或最小出口白名单，防 SSRF、数据外传和访问内网。
3. **如何防资源耗尽？**答题要点：CPU/内存/进程/时间/输出大小配额及并发限流。

## 自测
为一个虚构代码解释工具写安全需求：输入目录、网络、凭证、超时、输出大小和审计。
