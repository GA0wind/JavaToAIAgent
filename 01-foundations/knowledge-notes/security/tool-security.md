# Agent 工具安全

## 定义
工具安全是确保模型请求的动作只在可信主体授权范围内、以受限参数执行，并对副作用、重复调用、失败和审计进行治理。

## 原理
工具定义描述名称/参数，实际执行前由服务端验证调用者、资源范围、业务规则、风险级别和幂等性；高风险动作可要求用户确认或拆分为预览与提交。

## 为什么这样设计
模型可能选错工具、给出恶意参数或在重试中重复动作。将模型限制为“提出候选”而非“获得权限”，可复用现有业务安全体系。

## Java 工程关联
工具 DTO 做严格校验；查询工具只读且最小返回；写操作用幂等键、审批令牌、审计和补偿；工具异常做脱敏，避免将堆栈或秘密回传模型。

## 高频面试题
1. **如何防止工具越权？**答题要点：服务端身份授权、资源范围校验、工具白名单和审计。
2. **有副作用的工具怎么设计？**答题要点：幂等、确认、事务/补偿、预览和状态查询。
3. **模型可见完整内部错误吗？**答题要点：不应；返回可恢复、脱敏且不泄漏敏感信息的错误类别。

## 自测
将虚构“查询订单”与“更新订单”设计成不同风险工具，并定义执行前检查。
