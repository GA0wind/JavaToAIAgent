# Token、成本与延迟

## 定义
成本是一次任务使用模型、Embedding、重排、存储和计算资源的开销；延迟可分总响应时间、首 Token 延迟和各环节耗时。Token 是常见用量单位，但计价口径由服务商定义。

## 原理
一条 RAG/Agent 请求可能多次调用模型，输入、输出和缓存 Token 各有成本；串行步骤延迟相加，并行任务受最慢分支影响。重试会放大消耗。

## 为什么这样设计
质量只是系统目标之一，用户体验、预算与吞吐同样重要。按环节测量能找到真正瓶颈，避免以优化提示为名增加无必要步骤。

## Java 工程关联
每请求追踪模型调用数、Token 用量、工具次数、P50/P95、错误率和估算成本；设置硬预算、超时和并发限额。账单以官方价格和真实 usage 为准。

## 高频面试题
1. **怎样降低 Agent 成本？**答题要点：减少冗余上下文/循环，缓存可复用结果，按任务选模型，限制预算并以质量评测护栏。
2. **首字延迟和总延迟为何都看？**答题要点：前者影响感知等待，后者决定任务完成时间与 SLA。
3. **如何算单任务成本？**答题要点：合计各调用实际输入/输出 usage 与对应计价，纳入重试、Embedding、重排等成本。

## 自测
为一条合成流程拆分每阶段耗时和模型调用，计算不同重试次数下预算上限。
