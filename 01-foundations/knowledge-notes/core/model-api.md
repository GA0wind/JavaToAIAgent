# 模型 API 与消息协议

## 定义
模型 API 是应用向模型服务提交输入并接收结果的接口契约，包含消息角色、模型标识、参数、工具定义、响应、错误和用量信息。消息通常是有序序列，但各提供商字段和语义并不完全相同。

## 原理
服务端将请求映射为模型推理，返回完整响应或增量片段。应用需处理认证、限流、超时、取消、网络故障、供应商错误和 usage 元数据。

## 为什么这样设计
API 将模型推理包装成可集成的服务，使业务系统能复用远端模型而不自行托管训练基础设施。适配层降低供应商耦合，但不能掩盖能力和语义差异。

## Java 工程关联
把模型客户端作为受治理的外部依赖：配置凭证、超时、连接池、限流、重试白名单和错误映射；安全记录调用元数据，不默认记录原始提示。

## 高频面试题
1. **多轮对话如何保持上下文？**答题要点：应用持久化所需历史并按请求发送，模型 API 通常不自动跨请求记忆。
2. **模型适配层应统一什么、保留什么？**答题要点：统一基础调用、异常与监控；保留模型专有参数、能力和差异。
3. **所有模型错误都重试吗？**答题要点：区分可重试的网络/限流与永久参数/权限错误；考虑幂等、退避和总预算。
