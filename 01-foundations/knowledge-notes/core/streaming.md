# 流式响应

## 定义
流式响应是服务端在生成过程中分多段发送结果；它改善首段内容的等待体验，但每个分片都只是部分事件，不等于最终完整结果。

## 原理
客户端建立流式连接并逐条消费事件，累积文本、工具参数、元数据和结束状态。传输可中断，事件可能包含错误或取消，因此应用要区分内容增量与最终完成。

## 为什么这样设计
生成较长答案时，边生成边展示能降低感知等待，并支持进度反馈。代价是客户端状态机、背压、取消和部分结果处理更复杂。

## Java 工程关联
使用响应式流或异步 I/O 时定义缓冲、超时、断连取消、资源释放和最终事件语义。不要对每个片段单独 JSON 解析；工具调用参数须完整收集并校验后再执行。

## 高频面试题
1. **流式输出的主要收益与代价？**答题要点：降低首字延迟；增加生命周期与故障处理复杂度。
2. **客户端中途断开怎么办？**答题要点：传播取消、停止可取消的下游工作、释放连接并记录终止原因。
3. **可以边收到工具参数边执行吗？**答题要点：默认先累积、解析、校验，避免执行不完整或篡改中的参数。

## 自测
模拟正常完成、超时、用户取消和模型端错误，检查终态是否唯一且资源是否释放。
