# 结构化输出与 Schema 校验

## 定义
结构化输出是要求模型按 JSON 等机器可读结构返回数据，并尽量遵守给定 Schema。Schema 约束类型和形状，不自动保证事实正确、字段完整或业务规则成立。

## 原理
应用把字段、类型、枚举等格式说明传给支持该能力的模型；响应仍经过解码、解析、类型映射和业务语义校验。某些平台用约束解码，某些以提示和验证重试实现，能力不能一概而论。

## 为什么这样设计
结构化契约便于把自然语言任务接入服务代码和流程系统，也能更早发现格式错误。将格式约束与语义规则拆开，便于验证和审计。

## Java 工程关联
映射至 DTO 后执行 Bean Validation 和领域规则；未知字段、缺失值、数值范围和跨字段一致性要显式处理。材料抽取应同时保存证据片段，冲突或高影响项进入人工复核。

## 高频面试题
1. **JSON Schema 通过就代表结果可信？**答题要点：只证明格式符合约束，仍需证据、业务规则和权限检查。
2. **解析失败如何处理？**答题要点：有限修复/重试并保留原响应，超过预算则返回可诊断失败或人工复核。
3. **模型抽取如何审计？**答题要点：字段值、来源页/片段、模型/提示版本、校验结果和人工修订记录。

## 自测
设计材料字段 DTO，使“未发现”“空值”“冲突”和“需人工确认”有明确表示。
