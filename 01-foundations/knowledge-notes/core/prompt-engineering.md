# Prompt 设计与版本管理

## 定义
Prompt 是应用发送给模型的指令、上下文、示例和格式约束的组合。Prompt Engineering 是针对目标任务组织这些信息，并通过测试持续改进的过程。

## 原理
模型按消息序列预测后续 Token。提示可以明确角色、任务、输入边界、可用证据、输出格式和拒答条件；少样本示例提供模式，但占上下文且可能把偏差带入输出。

## 为什么这样设计
自然语言接口可快速适配多种任务，无需每个需求都训练模型。但提示本身是概率性控制手段，不是权限系统或确定性程序，故需要版本、评测和后端校验。

## Java 工程关联
模板与业务代码分离，参数显式传入，版本可追踪；对变更运行固定评测集，记录模型标识、模板版本和结果。用户输入和检索文档视为不可信数据。

## 高频面试题
1. **好的 Prompt 应包含什么？**答题要点：目标、边界、可信上下文、输出契约、失败处理；按任务验证。
2. **如何评估一次 Prompt 修改？**答题要点：冻结模型/数据条件，做基线对比，查看正确性、拒答、引用、安全、延迟与成本。
3. **Prompt 能防止越权吗？**答题要点：不能替代服务端认证授权、参数校验和隔离。

## 自测
为“根据检索证据回答、无证据明确说明”写模板，分别测试有依据、冲突和无答案问题。
