# 上下文工程

## 定义
上下文工程是为一次模型决策选择、组织并更新其可见信息的过程。它涵盖消息、系统提示、工具定义、任务状态、检索材料、历史轨迹和输出预算，范围大于上下文窗口本身。

## 原理
可把上下文看成观察空间：静态部分承载稳定指令和工具契约，动态部分记录当前任务与交互轨迹；每轮按任务选择必要信息，必要时检索、压缩、分层加载或隔离子任务。

## 为什么这样设计
模型的行动只依据当前可见信息；不相关或错误信息会分散注意、误导决策。显式管理还能控制 Token、延迟、缓存命中和隐私暴露。

## Java 工程关联
把可信配置、会话状态、检索证据和用户输入分区管理；按 Token 预算组装请求并记录来源。可变业务状态从权威服务读取，不依赖模型摘要维持一致性。

## 高频面试题
1. **上下文工程与 Prompt Engineering 区别？**答题要点：Prompt 是重要组成；上下文工程还管检索、工具、历史、状态、压缩和生命周期。
2. **上下文应该尽量多吗？**答题要点：不，按当前任务选择相关、可信且有权限的信息。
3. **一次 Agent 行动如何更新上下文？**答题要点：把动作、工具结果、状态和证据追加/归档，再决定是否继续或压缩。

## 自测
绘制一次 RAG 工具任务的静态前缀和动态轨迹，说明哪些信息应长期保留、按需加载或丢弃。
