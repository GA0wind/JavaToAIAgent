# KV Cache 与 Prompt Cache

## 定义
KV Cache 是自回归推理时保存已处理 Token 的 Key/Value 张量，避免每生成一个新 Token 都重新计算全部历史；Prompt Cache 通常指服务端复用相同请求前缀计算结果的缓存机制，二者层次不同。

## 原理
Transformer 注意力在逐 Token 解码时可沿用此前位置的 K/V。共享前缀若内容和排列稳定，部分服务可复用其计算；前缀之前插入动态内容或改变工具定义顺序，可能让后续缓存失效。细节依模型与服务实现。

## 为什么这样设计
缓存降低长提示和多轮调用的重复计算、延迟及资源成本；缓存约束也会影响上下文布局。缓存命中不能凌驾于正确性、权限或新鲜度。

## Java 工程关联
把稳定系统提示和固定工具契约放前面，动态状态放后面；不要将用户/租户内容跨请求错误复用。对比固定前缀、工具顺序变化和流式场景的实际成本/延迟。

## 高频面试题
1. **KV Cache 与会话记忆有何不同？**答题要点：KV Cache 是推理中间计算状态；记忆是应用存储和再次提供的信息。
2. **为何动态前缀会影响缓存？**答题要点：前缀内容改变后后续位置的上下文计算不再匹配。
3. **能否为了缓存把所有提示都固定？**答题要点：不能，时效、权限和正确性优先；仅稳定且安全的部分可缓存。

## 自测
设计静态系统提示/动态会话数据的消息顺序，并列出可能造成缓存失效的更新。
