# 上下文窗口与上下文预算

## 定义
上下文窗口是一次模型调用可处理的 Token 容量上限；上下文是该次请求实际提供给模型的消息和相关内容。窗口大小依模型而异，系统提示、历史、工具定义、检索片段和输出预留通常都要纳入预算。

## 原理
应用把本轮输入与必要历史、工具结果和检索内容组装为序列。超限时接口可能拒绝请求、截断或要求应用自行裁剪。模型只依据本次提供的上下文和参数工作，不会自动记住未发送的旧对话。

## 为什么这样设计
有限窗口约束推理计算和内存开销，也让服务能对延迟和资源做容量规划。应用必须选择与当前任务有关的信息，避免把全部历史机械重放。

## Java 工程关联
为系统提示、历史、工具 Schema、检索证据和回答预留预算；按 Tokenizer 估算而非 `String.length()`。裁剪需保留时间、否定、条件、来源和关键决定，并记录被省略内容。

## 高频面试题
1. **上下文窗口和记忆有什么区别？**答题要点：窗口是单次处理容量；记忆是应用跨请求保存、筛选和回注信息的机制。
2. **超窗如何处理？**答题要点：优先去重与相关性排序，再摘要/分段，保留关键约束和来源；输出留足空间。
3. **上下文越长效果越好吗？**答题要点：不一定，噪声、成本和注意力分散会影响效果，需用任务评测验证。
