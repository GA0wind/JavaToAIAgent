# ReAct（Reason + Act）

## 定义
ReAct 是交替进行推理与行动的 Agent 模式：模型基于观察决定下一步动作，工具结果再成为新的观察。工程实现中通常只需记录动作、参数、结果和简洁决策依据，不应要求公开隐藏思维链。

## 原理
循环为“问题/状态 → 选择动作 → 工具执行 → 观察结果 → 再选择或回答”。工具响应可能改变计划；必须验证参数和动作并设置停止条件。

## 为什么这样设计
仅凭一次生成处理复杂问题会缺少外部信息；交替行动让 Agent 能查询实时数据、发现错误并调整。但每轮都增加模型调用和攻击面。

## Java 工程关联
业务日志记录可审计的决策事件（选了哪个工具、为何符合业务规则、结果是什么），不要把内部推理文本当可靠解释或必需记录。对高风险动作加人工确认。

## 高频面试题
1. **ReAct 为什么能处理多步问题？**答题要点：工具观察能反馈新信息，下一步基于更新状态做决定。
2. **ReAct 与固定工作流如何取舍？**答题要点：步骤已知且规则明确用工作流；路径不确定且需探索才评估 Agent。
3. **怎么评测 ReAct？**答题要点：任务完成率、工具选择/参数正确率、步数、错误影响、延迟与成本。

## 自测
为一个只读查询任务记录三轮事件，明确哪一轮应终止并避免无意义重复调用。
