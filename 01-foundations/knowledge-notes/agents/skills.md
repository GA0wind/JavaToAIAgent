# Agent Skills 与渐进式披露

## 定义
Skill 是可按需加载的领域说明、流程知识、参考资料或脚本集合，用来补充 Agent 完成某类任务所需的能力。具体文件格式和执行语义由产品/框架定义，并非统一协议。

## 原理
先向模型暴露精简的 Skill 清单/描述；判断相关时再读取完整指令或资源，必要时调用其中引用的工具。这样将“常驻索引”与“按需细节”分层，限制上下文膨胀。

## 为什么这样设计
把所有操作规则和资料放在系统提示会挤占上下文并降低选择质量；渐进披露降低常驻成本，但依赖清楚的描述和正确的触发判断。

## Java 工程关联
把 Skill 内容视为可版本化配置和不可信输入：代码仓库评审、来源标记、权限最小化、发布审批。Skill 的文字不能授予工具权限，实际执行仍由后端服务控制。

## 高频面试题
1. **Skill、Tool、MCP 分别是什么？**答题要点：Skill 是按需加载的能力说明/资源；Tool 是可执行动作；MCP 是发现和调用外部能力的协议。
2. **如何避免 Skill 内容太长？**答题要点：短索引、分层文件、需要时加载，评测召回是否能正确触发。
3. **加载了 Skill 就保证遵从吗？**答题要点：不保证；仍需运行时约束、权限检查、输出/动作验证。

## 自测
把一份长领域指南拆成精简索引与两个按需章节，设计触发问题并做召回测试。
