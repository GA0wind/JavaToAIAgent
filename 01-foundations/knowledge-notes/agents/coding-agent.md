# Coding Agent（编码 Agent）

> 定位：进阶延伸阅读，不是当前 16 周主线必做项。

## 定义
Coding Agent 是能在代码仓库中观察文件、搜索、编辑、运行测试/命令并依据结果继续行动的 Agent。其可靠性来自模型与软件工程工具链共同作用。

## 原理
典型循环为理解任务、探索仓库、提出修改、应用补丁、运行检查、读取失败并迭代；文件系统和测试结果构成环境状态与反馈。版本控制提供差异检查和回退点。

## 为什么这样设计
代码可被编译、测试和静态分析，给 Agent 提供相对清晰的验证信号；把代码当作精确表达与工具适配能力，也能推广到规则、数据处理和报告生成。

## Java 工程关联
在隔离工作区执行，限制网络、凭证、文件范围、命令和资源；先跑针对性验证，再评审 diff。不要让模型对生产环境直接执行任意 Shell。

## 高频面试题
1. **Coding Agent 为何比通用电脑控制更易验证？**答题要点：测试、类型、编译、版本控制提供机器可检验反馈，但测试覆盖仍有限。
2. **模型修改代码后信任什么？**答题要点：实际 diff、构建/测试结果和人工审查，不信模型自述。
3. **如何治理生成代码的副作用？**答题要点：沙箱、权限限制、超时/配额、审批和回滚。

## 自测
在虚构仓库任务中执行只读搜索与局部修改，记录每次决策的真实工具结果和验证证据。
