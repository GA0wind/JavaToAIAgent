# Agent 规划（Plan-and-Execute）

## 定义
规划是把目标拆解为有序子任务并按依赖执行的模式。Plan-and-Execute 通常先产生计划，再由执行器逐步完成，必要时根据结果重规划。

## 原理
规划器生成步骤、依赖和完成条件；执行器运行一步并记录结果；评估器判断是否继续、修订计划或结束。计划应是可执行的状态数据，而非只保存在自然语言文本里。

## 为什么这样设计
先规划能提高复杂任务的步骤可见性和可控性；将规划与执行分离也便于重试、审批和监控。但过早规划可能错，计划必须能根据新证据调整。

## Java 工程关联
用 DTO 表达任务节点、输入、输出、状态和依赖；后端验证计划中的工具白名单及预算。对确定性步骤用代码排程，不把每个函数调用都交给模型规划。

## 高频面试题
1. **ReAct 和 Plan-and-Execute 有何不同？**答题要点：前者逐步交错行动和观察；后者显式先规划再执行，可重规划。
2. **计划如何处理工具失败？**答题要点：标记失败/重试/替代分支，保护依赖状态并满足幂等。
3. **计划为何不能直接照单执行？**答题要点：计划可能包含无效、越权或不可行步骤，需服务端验证。
