# 子 Agent（Subagent）

## 定义
子 Agent 是由上层 Agent/编排器委派的专门执行单元，通常有自己的目标、工具或受限上下文，并把结果返回给调用方。

## 原理
主 Agent 选择任务与子 Agent，传递必要输入；子任务独立执行并返回结构化结果；主流程合并、验证冲突并决定后续动作。并行调用可缩短可独立任务的总耗时。

## 为什么这样设计
分工可隔离专业提示和工具集合，降低单一 Agent 的上下文复杂度；并行能提升吞吐。代价是上下文复制、同步、成本、失败传播和结果一致性管理。

## Java 工程关联
将子任务建模为有界异步任务；限制深度、并发数、时间和预算。只传递最少必要数据，结果带来源/状态；主 Agent 负责最终授权和汇总。

## 高频面试题
1. **子 Agent 和普通函数调用区别？**答题要点：子 Agent 有模型驱动的独立决策循环；函数执行确定动作，成本和不确定性较低。
2. **哪些任务适合并行委派？**答题要点：相互独立且可汇总，注意共享状态和副作用。
3. **如何控制子 Agent 成本？**答题要点：任务预算、并发限制、模型分层、提前终止和去重。

把一个虚构资料审查拆给“格式检查”和“政策检索”两个只读子任务，定义汇总冲突规则。
