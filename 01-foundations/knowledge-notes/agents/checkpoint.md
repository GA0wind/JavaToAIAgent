# Checkpoint（检查点）与状态恢复

## 定义
Checkpoint 是在工作流/Agent 执行过程中持久化的一份状态快照，使长任务可暂停、恢复、检查或从失败节点继续。它通常与线程/会话标识和状态版本关联。

## 原理
每个节点完成后或关键转移时保存状态；恢复时加载最近快照并定位下一步。副作用步骤需记录执行状态或使用幂等键，否则从旧检查点重跑会重复写入。

## 为什么这样设计
长任务可能遇到进程重启、人工审批等待或模型调用故障；持久化比仅依赖内存更可靠，也支撑审计与人机协作。

## Java 工程关联
设计状态 Schema 版本迁移、保存策略、过期清理和敏感数据保护；事务边界需覆盖状态与业务动作，或用 outbox/幂等方案协调。

## 高频面试题
1. **Checkpoint 等于会话历史吗？**答题要点：不等同；它保存执行状态与恢复位置，历史只是可能的一部分。
2. **恢复后如何避免重复执行？**答题要点：执行记录、幂等操作、事务/补偿及节点完成标记。
3. **状态 Schema 更新怎么办？**答题要点：版本化状态并提供兼容迁移或拒绝旧状态的策略。

## 自测
设计一个需人工确认的操作状态，模拟服务重启后恢复并确保操作只执行一次。
