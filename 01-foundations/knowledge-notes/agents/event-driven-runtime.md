# 事件驱动 Agent 运行时

> 定位：超出当前 16 周核心实现的进阶主题，可作为长任务/异步产品延伸。

## 定义
事件驱动 Agent 运行时允许外部消息、计时器或工具完成事件唤醒 Agent；任务可能跨多个请求/进程持续，并需要排队、取消、抢占和恢复。

## 原理
事件进入队列后按优先级和任务状态路由；运行时加载 checkpoint、处理事件、产生动作并记录新状态。需区分快响应路径与慢推理任务，并处理重复事件、乱序、取消和用户不在线。

## 为什么这样设计
现实环境不会等待单次模型调用：邮件、设备状态和异步任务会在不同时间到达。事件化有助持续协作，但显著增加状态一致性和运维复杂度。

## Java 工程关联
采用队列/事件总线、持久化状态、幂等消费者、deadline、重试与死信治理；事件优先级和审批策略由确定性服务控制。模型不可用时应保留事件并进入明确状态。

## 高频面试题
1. **轮询和事件驱动如何取舍？**答题要点：事件驱动降低无效请求和响应延迟，但引入队列、顺序和重复处理复杂度。
2. **如何保证事件只处理一次？**答题要点：分布式系统通常不能简单假设 exactly-once；用幂等、唯一事件 ID 和状态机实现效果上的一次性。
3. **用户长时间不响应怎么办？**答题要点：超时、提醒、暂停/默认安全动作和人工接管必须按业务定义。

## 自测
画一个异步材料审核事件流，包含事件重复、审批超时、取消和服务重启后的恢复。
