# 幂等与工具调用副作用

## 定义
幂等表示同一操作被重复请求时，系统最终效果等价于只执行一次。它是重试、断线恢复和 Agent 重复调用中保护业务副作用的关键性质。

## 原理
调用方生成稳定幂等键，服务端记录请求状态/结果；同键重复请求返回已知结果或冲突。副作用执行与幂等记录需要一致性设计，可用数据库唯一约束、事务、outbox 或可补偿流程。

## 为什么这样设计
模型可能重复请求，客户端可能因超时不知道操作是否成功，工作流恢复也可能重放节点；没有幂等保护会重复扣款、重复提交或重复写入。

## Java 工程关联
工具接口明确幂等键、状态查询和业务唯一约束；区分“请求已接收”“处理中”“成功”“失败”。只读工具通常天然更易重试，写工具必须单独治理。

## 高频面试题
1. **超时后重试为什么有风险？**答题要点：服务端可能已成功但响应丢失，重试会重复副作用。
2. **幂等键怎么设计？**答题要点：稳定绑定业务动作与主体/请求语义，防跨用户冲突和滥用。
3. **数据库与外部系统如何保持一致？**答题要点：事务边界、outbox、状态机、补偿和对账，不声称跨系统天然原子。

## 自测
设计一个虚构“提交审核”工具的幂等状态表，推演请求超时后再次调用。
