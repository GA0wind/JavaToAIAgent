# 多 Agent 架构

## 定义
多 Agent 系统由多个 Agent 通过路由、委派、交接或共享状态协作完成任务。使用多个模型角色本身不自动带来更好结果。

## 原理
常见模式包括 supervisor 分派、handoff 转交、独立 Agent 并行后汇总、共享状态协作。系统需定义通信契约、终止规则、冲突解决、预算和故障策略。

## 为什么这样设计
复杂任务可按专业域或权限边界拆分，也可并行独立研究；但每个 Agent 的推理与通信增加成本、延迟和协调错误。

## Java 工程关联
先评估单 Agent/固定工作流基线，再通过任务依赖与评测证明多 Agent 有收益。集中管理授权、审计和最终副作用，不让 Agent 间共享未经筛选的全部数据。

## 高频面试题
1. **什么时候值得多 Agent？**答题要点：职责可清楚拆分、任务相对独立/并行，实测收益覆盖协调成本。
2. **多 Agent 如何避免互相循环？**答题要点：明确交接状态、最大深度/次数、终止条件和调用预算。
3. **如何比较单 Agent 与多 Agent？**答题要点：同一任务集测质量、成功率、延迟、Token/成本和安全事件。

## 自测
对一个多步骤任务画 Agent 交互图，标明每条消息的信息边界、超时和失败接管。
