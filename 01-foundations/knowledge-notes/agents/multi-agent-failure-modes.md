# 多 Agent 常见失效模式

## 定义
多 Agent 失效模式是由共享资源、信息传递、协调策略和共同模型偏差引起的系统性失败，包括并发冲突、错误级联、同质趋同、循环失控和责任推诿。

## 原理
Agent 的局部错误沿消息/共享状态传播；共享文件可能出现竞态或语义冲突；相似模型/提示会形成同源错误；没有预算和终止协议会反复委派。

## 为什么这样设计
局部 Agent 表现良好不代表组合系统可靠；必须评估协作层本身，并把控制平面、数据平面、权限和结果验收拆清楚。

## Java 工程关联
用工作副本、乐观锁、消息版本、幂等和所有权边界保护共享数据；独立来源交叉验证，预算/取消控制循环；汇总前验证输出并保留人工责任。

## 高频面试题
1. **如何防止错误级联？**答题要点：关键输出校验、独立验证、限制传播范围、故障隔离和提前终止。
2. **相同模型的多个 Agent 能算独立评审吗？**答题要点：不一定，错误相关性高；差异信息源/方法更有价值。
3. **如何处理并发修改？**答题要点：工作副本、版本校验、冲突检测和受控合并，避免最后写入覆盖。

## 自测
构造并行子任务写同一文件、共享错误证据和循环委派三种测试，定义可检测的失败事件。
