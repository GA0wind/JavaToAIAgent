# Agent Workflow（工作流）

## 定义
工作流是将任务表示成明确步骤和转换条件的编排。它可以完全确定，也可以在部分节点调用模型；Agent 是动态决策能力的一种，不是工作流的同义词。

## 原理
节点执行任务，边根据结果转移；支持顺序、并行、条件分支、循环、超时与人工审批。每个节点应有明确输入/输出和副作用边界。

## 为什么这样设计
显式流程可测试、重放和审计，适合业务规则稳定的步骤；在不确定的局部嵌入模型判断，可兼顾灵活性与可控性。

## Java 工程关联
简单流程可用 Spring 服务、状态机或作业编排实现；长任务要持久化状态并支持幂等恢复。选择框架前先明确并发、恢复和人工介入需求。

## 高频面试题
1. **何时用 Workflow 而非 Agent？**答题要点：步骤已知、风险高、需要稳定审计时优先显式工作流。
2. **如何设计并行节点？**答题要点：识别独立任务、限并发、处理部分失败并定义汇总语义。
3. **如何保证流程可重放？**答题要点：持久化版本化输入/结果和状态，控制非幂等副作用。
