# 工具发现与按需加载

## 定义
工具发现是让 Agent 从大量候选能力中识别、检索并加载当前任务所需工具的过程；按需加载则避免所有工具定义常驻上下文。

## 原理
可先按领域/类别提供目录，再用查询、子目录或元工具发现候选；通过描述与 Schema 选出少量工具供模型使用。工具变化、缓存和授权范围要纳入同步。

## 为什么这样设计
大工具集会增加 Token 开销并降低选择准确性；层次化发现将问题从“一次挑选海量工具”拆成“先定位类别，再选择具体能力”。

## Java 工程关联
工具目录只返回当前主体有权使用的能力；发现结果缓存要按主体/权限版本隔离，调用时仍二次授权。监测错误选择、发现漏失、轮次和成本。

## 高频面试题
1. **工具多了为什么效果可能下降？**答题要点：描述干扰、上下文膨胀、同类功能重叠和参数混淆。
2. **工具发现是否取代工具授权？**答题要点：不取代；隐藏未授权工具是辅助，执行时仍须验证。
3. **如何证明发现机制有用？**答题要点：在固定任务集比较选择正确率、漏选率、调用次数、延迟和 token 成本。

## 自测
为 100 个模拟工具设计两层目录和发现接口，加入授权过滤及不存在工具的回退。
