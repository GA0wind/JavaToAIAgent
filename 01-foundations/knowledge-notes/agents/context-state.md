# Agent 状态上下文（状态栏）

## 定义
Agent 状态上下文是由运行时维护、呈现当前任务进度和约束的结构化元信息，例如任务 ID、阶段、已完成步骤、预算、时间、待处理事件和终止条件。

## 原理
应用从权威状态机或工具结果生成状态摘要，放入请求或按模型支持作为元数据传递；每次状态变化都由程序更新并校验。状态栏是上下文的一部分，但不是业务事实的唯一存储。

## 为什么这样设计
长任务的消息历史不一定清楚表达当前进度、剩余预算或可执行动作；显式状态能减少重复工作并帮助模型遵守停止条件。

## Java 工程关联
用数据库/检查点保存事实状态，状态栏只作模型可读的投影；定义 Schema、版本和校验。不要让模型自行修改剩余额度、身份或审批状态。

## 高频面试题
1. **为什么不只依赖对话历史？**答题要点：历史是过程记录，状态是当前权威快照；长历史可能含冲突或过期信息。
2. **状态栏内容由谁维护？**答题要点：尽量由确定性运行时代码根据事件更新，模型只消费或提议。
3. **元信息错了会怎样？**答题要点：Agent 可能错误继续或提前停止；需来源、校验、审计和异常处理。

## 自测
为跨多步工具任务定义状态 DTO，并验证模型不能篡改用户、预算和阶段字段。
