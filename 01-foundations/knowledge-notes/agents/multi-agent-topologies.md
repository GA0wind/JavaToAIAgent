# 多 Agent 协作拓扑

## 定义
多 Agent 拓扑描述 Agent 之间如何分工、共享上下文和传递控制，常见有管理者/子 Agent、交接、对等协作与去中心化协作。

## 原理
共享上下文可保留细节但易膨胀和产生角色惯性；隔离上下文便于并行、模块化和权限划分，但需传递结构化任务包。协调器可路由和汇总，也可能成为能力瓶颈。

## 为什么这样设计
多个 Agent 的价值应来自新信息、独立验证、并行或可执行的能力分工，而不是角色数量本身。选择拓扑要对比质量增益、延迟、成本和错误传播。

## Java 工程关联
为子任务定义契约、状态、超时和预算；共享状态使用版本/锁，任务执行设取消和终止条件。权限由服务端集中执行，跨组织协议只解决互操作，不自动建立信任。

## 高频面试题
1. **Manager-Worker 与对等协作差别？**答题要点：中心路由/汇总与协商/消息传递的取舍，注意协调瓶颈和冲突。
2. **何时需要独立上下文？**答题要点：需要角色独立判断、隔离大量中间结果或并行执行时；必须设计交接信息。
3. **多 Agent 的第一判断标准？**答题要点：是否带来单 Agent 无法获得的信息/能力，收益是否超过额外 Token 与协调成本。

## 自测
对一项可拆分研究任务比较单 Agent、Manager-Worker 和并行独立验证三种拓扑的指标。
