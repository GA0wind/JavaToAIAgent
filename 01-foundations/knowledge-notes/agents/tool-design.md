# Agent 工具设计

## 定义
工具是 Agent 可请求执行的原子或有限业务能力。工具设计包含名称、描述、输入/输出 Schema、权限、错误语义、副作用和验证方式。

## 原理
模型根据工具描述选择动作并填参数；宿主校验后调用实现，再将真实结果返回模型。描述和 Schema 必须与执行行为一致，输出应提供完成下一步所需的信息而非无边界数据。

## 为什么这样设计
清晰契约提升工具选择和参数正确性；窄能力更易授权和审计，合理聚合可减少冗余调用。工具越多、越模糊，模型越难选且攻击面越大。

## Java 工程关联
服务端重新做 Bean/领域校验、认证授权、限流、幂等和审计；只读接口可支持分页与缓存，写操作拆分预览/提交并验证最终状态。模型可见参数必须等同真实执行参数。

## 高频面试题
1. **工具描述怎样写？**答题要点：说明用途、适用/不适用条件、参数含义、单位、副作用和错误边界。
2. **工具应该做大还是做小？**答题要点：按职责和可验证性设计；通用性与权限/参数复杂度之间权衡，并用评测比较。
3. **工具返回什么最有用？**答题要点：可靠、简洁且足以支持下一步判断的结果，包含状态和必要来源。

## 自测
将一个宽泛的“处理客户问题”工具拆成有限只读查询与经确认的写操作。
