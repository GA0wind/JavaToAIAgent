# Harness Engineering

## 定义
Harness 是围绕模型构建的运行时和保障层，连接上下文、工具、流程、校验、权限、恢复与观测，使模型能力能在明确边界内完成任务。它不是某一个 Agent 框架或 Prompt。

## 原理
Harness 组织模型输入和可用动作；执行前校验，执行后检查真实状态；遇错时重试、修复、暂停、交给人或终止；并记录轨迹供评测。它弥补模型尚不稳定的环节。

## 为什么这样设计
生产任务关心稳定完成、权限和成本，不只是模型偶尔答对。将不可变规则与外部验证放到应用层，可以隔离模型输出波动；模型能力进步后可逐步简化冗余护栏。

## Java 工程关联
将身份、领域规则、事务、预算、幂等和回滚放在可测试服务中；模型仅负责概率性理解或提出动作。Harness 各策略需有评测证据，避免无依据堆叠兜底。

## 高频面试题
1. **Harness 的价值是什么？**答题要点：把概率模型接入可靠的上下文、执行、验证与恢复闭环。
2. **模型更强后 Harness 是否消失？**答题要点：可删掉已稳定内化的部分，但业务约束、最新状态和责任边界仍需外部保障。
3. **Harness 与 Agent Framework 的关系？**答题要点：框架可以实现其中的编排组件；Harness 是系统职责/设计视角，未必依赖特定框架。
