# Agent 记忆

## 定义
Agent 记忆是 Agent 工作流跨步骤或跨会话保存、读取和更新的信息，可能包括当前任务状态、短期对话历史、长期偏好或可检索经验。

## 原理
短期状态随工作流节点传递并可通过 checkpoint 持久化；长期记忆需经过筛选、索引、权限检查和召回，再作为上下文注入。二者不应混为一个无边界的文本历史。

## 为什么这样设计
任务需要跨轮连续性，但模型调用本身通常不保留应用状态。分层记忆把可恢复流程状态与可检索知识分离，便于一致性、容量和隐私治理。

## Java 工程关联
业务事实从权威服务查询；对话摘要和偏好保存来源与更新时间；为租户、用户设置访问/删除策略。任何记忆召回都应经过权限过滤。

## 高频面试题
1. **短期状态与长期记忆差异？**答题要点：短期服务当前流程连续性；长期记忆跨会话检索稳定信息，治理要求更高。
2. **Agent 能自行写入记忆吗？**答题要点：可提议写入，但应用按授权、隐私、可信来源和保留规则裁决。
3. **如何避免旧记忆误导？**答题要点：来源/时间、过期、冲突检测、权威系统校验和用户纠正能力。

## 自测
设计记忆写入准入规则和删除接口，解释某条信息为什么保留或拒绝。
