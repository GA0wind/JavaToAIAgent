# Agent

目标：理解模型决策与后端执行的边界，设计可终止、可恢复的工具流程。关联第 9～12 周；[面试题 AGENT-01～06](../../04-interview/question-bank/agent.md)。整理日期：2026-11-05；个人掌握与实践状态：未开始。

## 核心概念

| 概念 | 含义 | Java 经验对应 |
|---|---|---|
| Tool Calling | 模型生成工具名与参数请求，应用决定是否执行并返回结果 | 受控 RPC 调度；模型响应不是授权凭据 |
| Agent | 本文指让模型在约束内动态决定下一步、使用工具并根据结果继续执行的系统 | 调度策略含模型决策的状态机；不要求一定有多个模型 |
| Workflow | 主要执行路径由程序预先定义，可在节点中使用模型 | 工作流引擎、状态机、条件分支 |
| ReAct | 将推理与动作交替，利用外部观察继续决策 | 循环中的决策、执行、读取结果；不同于前端 React |
| 短期记忆 | 当前会话与任务状态 | 请求上下文、会话状态；需隔离和容量管理 |
| 长期记忆 | 跨会话保留并按需读取的事实或偏好 | 有来源、权限、期限的数据存储，不等于全部聊天历史 |
| 人工确认 | 对具体动作及其参数进行确认后再执行 | 审批单关联到实际命令，确认后不能任意改参数 |

工具职责见 [F07](../../02-resources/official-docs/foundation-sources.md#f07)；ReAct 见 [P04](../../02-resources/papers-and-articles/foundation-papers.md#p04)；Workflow 区分见 [P05](../../02-resources/papers-and-articles/foundation-papers.md#p05)。Agent 定义在不同资料中有差异，面试时先说明自己的使用范围。

## 最小工具循环（设计示意，未实现）

```text
加载任务和认证上下文
在步数、时间、Token/费用预算内：
    调用模型
    若给出最终回答：校验后结束
    若请求工具：白名单 → Schema → 权限 → 必要确认 → 执行 → 记录结果
    将有限且经过处理的结果加入上下文
超过限制或不可恢复错误：返回明确失败状态和可用证据
```

可以让模型建议查询 `queryDemoStatus(demoId)`，但用户身份来自服务端。演示 ID 与返回数据均应合成。工具返回中的文本仍是不可信外部输入，不能让它修改权限或执行策略。

## 状态、恢复与记忆

持久化任务 ID、步骤、工具调用 ID、参数摘要、执行状态和必要结果。进程恢复前区分“尚未执行”“已成功”“结果未知”；请求超时不表示外部动作没有发生。对于写动作，使用稳定业务幂等键、执行账本及状态查询；模型供应商返回的调用 ID 未必能跨新请求稳定复用。

历史压缩保留当前目标、关键约束和证据出处，摘要需要核对。长期记忆要有有效期、来源与删除方式，过期偏好不能覆盖当前明确要求。这些是基于后端经验提出的设计建议，尚未做恢复实验。

## 易错点

- 多加几个工具不自动构成可靠 Agent；固定业务链路通常可先用 Workflow。
- 多 Agent 带来通信、冲突、成本和排障复杂度，收益要通过任务拆分及评估证明。
- 模型自述“成功”不等于工具成功；应以执行结果和业务状态为准。
- 审计以输入输出摘要、工具动作和状态为主，不依赖模型披露完整内部推理。
