# RAG

目标：说明知识如何进入回答，答错时能沿链路定位。关联第 5～8 周；[面试题 RAG-01～06](../../04-interview/question-bank/rag.md)。整理日期：2026-11-05；个人掌握与实践状态：未开始。

## 两条链路

```text
索引：获授权资料 → 解析清洗 → 分块 → Embedding → 向量及元数据入库
查询：认证/权限条件 → 问题处理 → 召回候选 → 重排/去重 → 组织证据 → 生成 → 校验引用
```

RAG 把外部资料作为生成上下文，通常不改模型权重。现代应用流程与原论文的训练和检索实现不必完全相同。依据：[P03](../../02-resources/papers-and-articles/foundation-papers.md#p03)、[F06](../../02-resources/official-docs/foundation-sources.md#f06)。

## 核心概念与取舍

| 概念 | 作用 | 常见问题 |
|---|---|---|
| Chunk / overlap | 将长资料切成可检索单元，重叠保留边界上下文 | 太小丢条件，太大混入噪声；没有通用最佳大小 |
| 元数据 | 保存来源、版本、有效范围、权限标签和定位信息 | 只有文本和向量时，难以追溯和执行隔离 |
| 向量检索 | 在语义表示空间找邻近内容 | 相近表述可能含相反结论；精确编号不一定命中 |
| BM25 | 基于词项匹配及统计权重排序 | 对术语、编号有价值，但不等价于语义理解 |
| 混合检索 | 合并关键词和向量的候选 | 两路分数尺度不同，不能无条件相加；可按排名融合后评估 |
| Reranker | 对问题与候选联合评分，改善候选顺序 | 只处理已有候选，救不了完全漏召回的证据 |
| Top-K / 阈值 | 控制候选量与最低相关性要求 | K 增大可能增噪、增成本；分数不能直接当正确概率 |
| 向量索引 | 让近邻搜索更快，可做精确或近似搜索 | 近似索引可能牺牲召回；需要和精确结果比较 |

向量搜索及 HNSW / IVFFlat 边界见 [F12](../../02-resources/official-docs/foundation-sources.md#f12)；Cross-Encoder 重排见 [F13](../../02-resources/official-docs/foundation-sources.md#f13)。检索器使用的 Embedding 空间必须兼容，换模型时即使维度相同，也不能默认混用已有向量。

## 从 Java 数据工程理解

索引链路类似 ETL，查询链路类似带排序的搜索服务。文档版本更新要考虑旧块失效、重建索引和可回溯；Embedding 不是哈希，不具备唯一性保证。租户条件由服务端注入检索查询，返回内容在进入模型前必须属于当前用户可见范围；不要把“检索后过滤”误解为可以先把无权限原文发送给模型。

检索后只附来源列表不等于答案有依据：需核对结论是否由对应片段支持，文档是否仍有效，条件是否匹配；无证据、证据冲突和工具故障应分别说明。

## 答错时的排查顺序

1. 原资料是否包含正确依据，解析是否丢表格、标题或条件？
2. 分块是否割裂上下文，版本和权限标签是否正确？
3. 目标片段是否进入召回候选，是否被阈值、近似索引或过滤影响？
4. 证据是否在重排、去重和上下文裁剪时丢失？
5. 生成是否忽略证据或扩大结论，引用是否对应？

这是本仓库的排障框架，不是已发生的项目故障记录。
