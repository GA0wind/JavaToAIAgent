# Java 与 Spring AI

目标：把模型作为受治理的外部依赖接入 Spring 服务。关联第 1～3、9～14 周；[面试题 JAVA-01～05](../../04-interview/question-bank/java-spring-ai.md)。整理日期：2026-11-05；个人掌握与实践状态：未开始。

## 组件职责

| 组件 | 作用 | Java 经验对应 |
|---|---|---|
| `ChatModel` | 面向聊天模型的底层抽象 | 外部服务适配接口，具体实现连接提供商 |
| `ChatClient` | 组织消息、选项和调用流程，支持普通及流式调用 | 面向业务的调用构建器，不是模型本体 |
| `Advisor` | 在调用流程中组合上下文、检索等能力 | 可类比拦截器链；顺序会影响输入与执行行为 |
| `EmbeddingModel` | 生成向量表示 | 独立模型依赖，不负责生成回答 |
| `VectorStore` | 保存与检索向量及元数据 | 检索抽象，不等于特定数据库 |
| 输出转换 | 将文本响应映射到 Java 类型 | 类似反序列化，仍需 Schema 和业务校验 |
| Tool | 提供有名称、描述和参数的业务能力 | 受控 Service 入口，不应直接暴露任意 DAO |

依据：[F04～F07](../../02-resources/official-docs/foundation-sources.md#f04)。本轮参考动态文档，访问页显示 Spring AI 2.0.2；这不是项目选型或兼容性验证，仓库尚未新增构建依赖。

## 一次请求的职责划分

`Controller → 身份/配额检查 → Application Service → ChatClient/模型适配 → 响应校验 → 返回`

身份和租户来自认证上下文；业务规则在服务端执行；Prompt 管理任务说明和表达方式。框架能减少接入代码，但不能替代领域校验、权限隔离和故障策略。

### 结构化输出

区分三层：Prompt 请求 JSON、文本转换器解析映射、提供商支持的原生 Schema 约束。支持范围与失败形态随模型和接口变化。即使反序列化为 DTO 成功，也要检查必填字段、枚举、数值范围以及证据来源；不能让模型生成的“已授权”字段充当授权凭据。[输出转换依据 F05](../../02-resources/official-docs/foundation-sources.md#f05)。

### 流式响应

流式将增量内容逐步交给客户端，改善等待体验，不保证总耗时或成本降低。HTTP SSE 可承载文本、工具状态、结束和错误事件；片段可能不是完整句子，更不一定是可解析 JSON。需要处理聚合、客户端断开、取消、超时与流中失败。

调用模式见 [F04](../../02-resources/official-docs/foundation-sources.md#f04)；上述 SSE 事件组织是练习设计，不是固定协议要求。

## 从 Java 后端迁移的工程原则

- 长耗时调用采用适合实际负载的并发模型，限制在途请求；不能在事件循环中直接执行阻塞操作。
- 设置端到端预算与单次调用超时；重试只用于适合重试的临时故障，次数和等待都计入预算。
- 工具有副作用时单独处理幂等；重试模型请求不能等同于重做业务动作。
- 记录模型标识、Prompt 版本、Token、耗时和错误分类；敏感原文不作为默认日志。[观测依据 F10](../../02-resources/official-docs/foundation-sources.md#f10)。
