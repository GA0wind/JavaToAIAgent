# 安全

目标：把模型视作不可信决策输入，把权限和执行边界保留在后端。关联第 6、9～14 周；[面试题 SEC-01～04](../../04-interview/question-bank/security.md)。资料核验日期：2026-11-05；个人掌握与实践状态：未开始。

## 核心概念

| 概念 | 含义 | Java 经验对应 |
|---|---|---|
| 直接提示注入 | 用户输入试图改变原任务与约束 | 对不可信请求的语义攻击，不能仅靠字符串过滤 |
| 间接提示注入 | 外部文档、网页或工具结果夹带指令 | 类似把外部数据误当可执行逻辑，但不是传统 SQL 注入的同一机制 |
| 最小权限 | 工具和服务账号仅拥有完成任务所需能力 | 服务端鉴权、资源级校验和网络边界 |
| 输出校验 | 检查结构、参数范围、引用和执行条件 | DTO 校验加领域规则；不能直接执行模型生成 SQL 或命令 |
| 人工确认 | 对有副作用的具体动作提供审核机会 | 确认对象应绑定参数、目标、有效期和执行身份 |
| 数据最小化 | 只传任务必要且获授权的数据 | 出站请求和日志都需要控制，不只是页面脱敏 |

提示注入定义与缓解原则见 [F18](../../02-resources/official-docs/foundation-sources.md#f18)；MCP 特有边界见 [F17](../../02-resources/official-docs/foundation-sources.md#f17)。这些措施降低风险，不能声称彻底消除注入。

## 需要代码强制的边界

1. 身份、租户和资源权限来自认证上下文，不能信任模型参数中的身份声明。
2. 检索限定可见数据；共享缓存必须包含权限范围和资料版本，命中后仍应满足当前授权。
3. 工具实行白名单、参数校验、操作级授权、超时和调用限额；模型只能提出请求。
4. 对外部返回内容保留来源并按数据处理，不允许它扩充工具、覆盖权限或要求泄露密钥。
5. 写操作确认绑定到待执行内容，执行前再次检查权限和状态；审批不是永久通行证。

这是本仓库的设计要求，尚未实现权限模块，也未通过安全测试。

## 日志和审计

优先记录请求 ID、模型与 Prompt 版本、耗时、Token、错误分类及脱敏工具摘要。Prompt、文档原文和工具结果可能带敏感信息，调试日志和 trace 同样要控制读取权限与保留时间。可观测性默认行为参考 [F10](../../02-resources/official-docs/foundation-sources.md#f10)，不要把框架默认配置当作完整的数据治理方案。
