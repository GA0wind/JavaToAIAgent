# Token 与分词器

## 定义与原理

**Token** 是模型输入编码使用的离散单位，可以是字、子词、字节片段、空格/标点或特殊标记；它不等于一个汉字或一个完整单词。**Tokenizer** 按特定词表和规则将文本编码为 Token ID，模型处理 ID 序列，输出再由对应解码器还原成文本。

BPE 等子词方法在训练时统计常见相邻片段并学习合并规则；使用时应用已学规则。字符级切分词表小、覆盖灵活，但序列长；整词级切分更直观，却容易遇到词表膨胀和新词覆盖问题。子词方案在词表规模、覆盖能力和序列长度之间折中。不同模型的 Tokenizer 不同，同一文本可能有不同 Token 数。

## 为什么工程上要关心

- 上下文窗口按 Token 容量计算；系统提示、历史、工具定义、检索片段和输出预留都会占预算。
- Token 数影响推理工作量；若 API 按 Token 计费，也影响用量。实际费用取决于提供商、模型和输入/输出等计价规则，应以官方价格与响应 `usage` 为准。
- Java 的 `String.length()` 计量单位与 Token 不同，不能用它判断上下文是否超限。
- 过长历史、重复工具说明或过多检索结果会挤压有效上下文；压缩时要保留来源、否定、条件和时间信息，并通过评测检查效果。

## 常见面试题与答题要点

1. **Token 是什么？**模型输入编码的单位，由模型对应的 Tokenizer 切分；不是固定的字、词或语义单位。
2. **为什么不按字符或完整单词切分？**字符级序列可能太长；整词级词表难覆盖形态变化和新词；子词方法做折中。
3. **BPE 大致怎么工作？**训练时从基础符号出发，反复合并高频相邻符号对并保存规则；推理时使用已学习的规则编码文本。
4. **中文一个字/英文一个单词固定对应几个 Token 吗？**不固定，取决于具体 Tokenizer、词表和文本。应使用目标模型的计数工具实测。
5. **Token 数为什么与成本和上下文有关？**Token 是上下文容量和许多 API 用量统计的单位；不同服务的价格口径不同，不能从字符数直接推算账单。
